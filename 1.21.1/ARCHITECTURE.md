# Minecraft 模组架构

更新：2026-11-04，v0.49.0；Minecraft 1.21.1 / NeoForge 21.1.265 / Java 21。本文描述当前实现；历史迁移取舍见 `../1.20.1/docs/迁移设计.md`，审查证据见 `../1.20.1/docs/当前模组状态审查.md`。

## 依赖边界

| 模块 | 职责 | 允许依赖 |
|---|---|---|
| `domain` | 不可变创建定义、定点资源、VM、运输账本、完整运行快照 | Java 标准库 |
| `application/runtime` | 世界步阶段、稳定身份顺序、重复身份拒绝、宿主故障隔离 | domain、Java 标准库 |
| `application/observation` | 客户端与服务器共用的独立观察值 | domain、Java 标准库 |
| `adapter` | 纯 JSON、资源加载、文本码 | domain、共享观察、Gson |
| `adapter/persistence` | Minecraft NBT 格式、历史迁移、物品聚合仓储和变更提交 | domain、编解码、Minecraft 数据类型 |
| `server` | 输入用例、装备解析、权限、世界适配与装配 | 上述核心和 Minecraft 服务器 API |
| `client` | 配置草稿、界面输入、布局与渲染 | 独立观察、创建定义、网络客户端适配 |
| `network` | 有界传输和线程/逻辑端适配 | 两端入口；只能把意图交给服务器用例 |

领域和应用核心不得引用 Minecraft、Forge、服务器服务、客户端控件或 JSON/NBT 编解码。`RuntimeArchitectureContracts` 把这个规则纳入正常回归。`AssemblyInspection` 已移出客户端包，编解码不再依赖客户端类。`CircuitSnapshot` 是独立领域状态；抽象 `MagicCircuit` 不再通过返回类型依赖具体 `TickCircuit` 内部类。

## 固定步所有权

`CircuitScheduler` 唯一拥有跨宿主推进顺序。`WorldCircuits` 只收集物品任务和已加载固定设备、按物理 ItemStack 去重，再装配宿主与世界网络。

1. 载入聚合，按 UUID 排序；同一身份的多个物理实例都拒绝推进。
2. 宿主在执行边界重验物理持有、同一世界、存活、装备与锚点；失效装备停止供给并在边界保存。
3. 清除上步外部驱动，交付世界旧运输，再交付载体内部旧运输。
4. 由宿主提供有限 `ManaSource` 和步数，推进各独立 VM；已交付的输出交给宿主执行 Minecraft 效果。
5. 发布内部新运输，再发布世界新运输。
6. 宿主提交变更。待机聚合不会创建完整快照或序列化 JSON。

`CircuitHost` 提供供给、步数、输出执行、提交及故障报告；`CircuitExchange` 提供世界网络的接收和发布。二者都可以用纯 Java 测试宿主替代。单个宿主失败会立即停供并从本步端点解析中移除，停止现场仍进入提交；故障报告本身抛错不阻断其他宿主。重复身份的全部实例都停止并提交；其他宿主继续；不把 Minecraft 世界写入包装成可回滚领域事务。

`MinecraftCircuitHost` 负责装备和世界能力转换。移动装备共享玩家槽；固定设备使用自己有限的本地储量、位置、方向及所有者 UUID。固定设备推进不查找在线玩家，也不强加载区块、补算现实离线时长或自动补能。动作权限与运行资格分别校验；所有者离线时，玩家/方块作用遵循保守权限规则，不能把所有者变为匿名施法者以放宽权限。

## 应用入口与存储

- `CarrierCommands`：验证目标与槽位、材料消费、配置替换、起停、开关、互联和逻辑复位。
- `CarrierEditor`：构造独立管理观察与编辑器响应，不推进 VM、不保存现场。
- `CastPermissions`：保留所有者身份；缺失所有者拒绝玩家作用与方块修改，不降级为匿名授权。
- `CastingEquipment`：解析主手法杖和副手法术书的关系；运行不依赖书籍界面服务。
- `MaterialInventory`：材料板查询、消费定位及回收，供命令和观察共享。
- `CarrierFaults`：停用标志及错误反馈，保留损坏根记录，不创建替代法阵。
- `CarrierService`：现有物品和网络调用的薄兼容入口，不持有缓存或实现调度。
- `CarrierRepository`：每个物理 ItemStack 的唯一活动聚合；NBT 为提交/搬移副本，弱缓存保存服务器线程上的活动实例。外部整条 NBT 替换会使缓存失效；禁止绕过仓储原地修改它管理的编码。
- `NotebookRepository`：不可变蓝图簿创建配置；与法术书完整运行聚合分开存储。

完整程序集和蓝图簿使用 `{Format:1, Utf8:byte[]}`。编码前检查 UTF-8 字节上限，读取拒绝非法编码和未知版本；不是单个 StringTag，不受其 65535 字节写入限制。程序集保留 1 MiB、卷册保留 512 KiB 的原有总限额。内层程序集 v1、卷册 v1 不变；VM 含汲取符文时为 v5、旧图仍为 v4；接受并完整恢复合法 v1–v5 现场，旧协议不能携带新汲取符文；旧字符串/旧单 VM 只有完整校验成功才替换为新编码。已经被旧版写空的数据无法凭空恢复。

`CircuitAssembly.ChangeStamp` 包含选中项、槽位结构、各 VM 变更令牌和内部网络令牌。令牌只在内存使用，不进入存档，也不承担玩法计数。嵌套 VM 的起停、收发包、驱动/门态、逻辑复位和推进都会使聚合变更可见；网络全部损耗为零载荷时，账本变化同样触发提交。空操作不改变令牌。固定方块仅在聚合改变时标记区块；玩家槽按小型状态值变化保存；世界网络按自己的令牌标记 SavedData。

## 锚点与异常收尾

世界互联 SavedData v2 保存锚点位置、所有者和确认销毁状态。实际方块替换由 `CircuitBlock.onRemove` 记录；区块卸载和实体 `setRemoved` 只注销调度，不把端点判为销毁。若移除通知因外部方式遗漏，拆线时只检查已加载的原锚点，不强加载区块。

正常拆线仍要求两端停供并排空。确认一端销毁后，仅同一所有者可在剩余设备停止后清理；`CircuitLinks.abandon` 将在途量完整计入损耗，不向剩余法阵退款。回收物品在新位置放置不会冒充原运输端点；原线路清理前，其运行资格保持失效。

v1 网络可以读取并保存为 v2；缺失的所有者字段不猜测补齐。旧端点在升级前就丢失且缺少所有权证据时仍拒绝自动清理，需要额外恢复途径。损坏网络保留原 NBT 并停用。

## 生命周期与交互状态

`TickCircuit.Phase` 从权威状态推导，不新增一份可与 `powered` 矛盾的持久化枚举：`RUNNING` 继续支付、求值和输入；`DRAINING` 停供但仍有阵内缓存/在途；`QUIESCENT` 没有可独立推进的阵内内容。回收储备、发送口待发包不要求 VM 空转，调度层仍交付/发布网络。阻塞在关闭通路的残余仍逐步检查，尚未实现完整依赖唤醒。

停供保持门态、计数/相位/锁存及真实残余；手动重启只重开输入窗口、清除外部驱动和对外输出有效位、解除边沿武装，不丢弃控制记忆。外发信号须重新成功支付控制步骤才有效。恢复拒绝耗尽窗口却仍供电、单次/持续注入计数矛盾及不可能的玩家恢复等待组合。

世界法术 SavedData 当前 v8，读取合法 v1–v7 时显式升级，保留飞行、派生队列、屏障现场。整型计数、严格布尔、列表类型、所有者和出生姿态都在进入活动态前校验；坏数据保持原 NBT 并停用。未加载弹道和屏障冻结，不更新寿命或反复标脏；冻结屏障也不参与已加载弹道碰撞。临时光照继续使用已有的独立租约状态和原方块匹配恢复。

`EditorRequests` 只保存一份当前等待：空闲、刷新等待或修改等待。每次请求有独立 UUID；修改取代旧刷新，修改等待期间拒绝新请求，迟到/重复/未知回复忽略。100 个客户端逻辑步超时后显示结果未知并允许再次刷新，不自动重发修改。子页保留父控制器等待状态，切页取消未完成的落笔/拖动。网络协议`1.21.1-12`要求两端一致。

## 静态美术与批次特效

`art/inkscape/runes.svg` 是符形矢量源，`assets/elementalcircuits/art/glyphs.json` 保存派生索引和几何契约；`tools/artwork/bake-art.py` 调用Inkscape离线导出符形和指针，并生成其他GUI及特效资源。运行时不执行资源生成器。`RuneShapes` 读取不可变索引，原生指针读取导出的PNG；`GlyphAtlas` 用共享纹理和四边形绘制界面符形。动态线路每段只提交一个四边形，布局、命中测试和线路损耗独立于贴图。

`SpellVisual` 是只读表现观察，不含伤害、资源或权威对象；`VisualBudget` 负责有界队列与观察者范围筛选。服务器 `SpellVisuals` 在世界步内收集观察，在法阵、弹道和实际光照结算后按玩家分批发布。光束同步实际裁切后的端点，飞行同步已完成的线段，屏障同步位置／法线／半径。原版逐点粒子广播已退出模组路径。

`VisualNetwork.Batch` 携带维度和世界步，只允许服务端到客户端；每包最多128条，每玩家每步最多512条，世界观察队列最多1024条。长光束按线段距观察者筛选，不能只按中点过滤。未加载对象继续遵循既有冻结规则，不为视觉加载区块；卸载清理发件箱。

客户端 `SpellVisualClient` 独占当前世界的 `VisualTimeline`，跨世界引用／维度不匹配、过旧观察和退出均有处理；暂停不推进本地寿命。最多2048个活动观察，过期移除；表现过载只丢弃视觉观察，不丢弃权威 tick 或命中。`SpellVisualRenderer` 在 `AFTER_PARTICLES` 用同一材质／着色器绘制，深度测试开启、深度写入关闭，每帧最多8192个四边形，一次法术批次绘制。没有客户端碰撞或预测命中。

`art/effects.json` 保存短期视觉寿命、宽度、透明度、图集格和表现数量；资源重载先完整验证再发布，并清空旧特效。纹理走原生资源重载，制作时改矢量源后需重新烘焙。美术改变不升级 VM 或世界保存版本。详细验证和范围见 `../1.20.1/docs/静态美术与批量特效.md`。

0.26的`ElementalGeometry`按元素生成喷流、岩片、气流、电弧、旋涡和符印，`SpellAtlas`选择离线动画帧；`tools/artwork/bake-spell-assets.py`将六份CC0来源适配为64格单一图集，运行时不再读取旧`spells.png`。时间线分别维护剩余寿命与动画相位，刷新不会反复重播第一帧。

`ElementalCombos`负责纯规则，`LightningBeams`负责权威链。纯正雷束默认两跳，显式连锁可覆盖；同一调用内按可见性、权限、已访问名单、跳距和剩余总射程选择目标，各接触共享原预算，后跳计损耗。分裂/爆破组合保留既有管线。屏障v8保存元素，旧版明确迁移为原奥术外观，不改变容量寿命。详细组合矩阵和测试见`docs/art/元素组合与奇幻特效.md`。

## 施法音效

`SpellSound` 是独立、可丢弃的声音观察，包含阶段、元素与位置；它不依赖粒子或客户端渲染，不进入法阵快照、蓝图和世界法术保存。成功起阵提交后由 `CarrierCommands` 发布起动声，实际显化由 `SpellEffects` 发布发射／屏障展开声，权威接触与结算发布命中声。屏障刷新和飞行尾迹不逐步发声，起阵拒绝、停供和无元素输出不会误播起动／发射声。

`AudioPolicy` 与 `SoundBudget` 是纯 Java 表现策略：按世界步、阶段及4格空间单元合并重复；世界步接收至多64条，每玩家从24格内优先听到最近8条。冷却记录自动过期，最多768条；排空队列不能重置同一步接收预算；步末之后到达的命令观察保留到下次发布，不被新步覆盖。过载仅丢弃声音，不改变伤害、资源或弹道。

`SpellSounds` 在世界步结算后发送原生 `ClientboundSoundPacket`，没有新增自定义消息或客户端声音状态机。Minecraft 声音系统负责空间衰减、“玩家”音量、字幕、声道回收、资源重载及退出清理。世界卸载清理观察队列与冷却；声音种子不消耗玩法随机源。`audio/policy.json` 是启动读取的表现配置。0.23起，`art/audio/recipes.json` 冻结39个已核验授权源文件的哈希与混音参数，`tools/artwork/bake-audio.py` 离线生成74个44.1kHz单声道OGG、28个事件的变体表以及逐素材许可清单。旧占位音只在美术参考目录保留。运行时不合成波形，原始源包及工具不打入JAR。授权、制作和验证见 `docs/art/奇幻音效素材与适配.md`。

## 当前边界

这次重构关闭调度依赖、活动状态与提交耦合、客户端 DTO 反向依赖及大 NBT 丢失等已复现问题。Minecraft 适配仍包含静态装配入口；`JsonCodecs` 和 `WorldSpells` 仍集中处理多个相近子领域。逐点粒子广播现已改为客户端形状观察和有界绘制；长时 GC、整服 TPS、多人带宽和正式生存体验仍未完成验收。不得把局部调度提速写成全部性能问题消失。


## 1.21.1平台适配

构建使用ModDevGradle 2.0.148与Gradle 9.2.1。领域和应用层没有因平台迁移而改变；网络与Minecraft存储变化封装在适配层。迁移证据见 `docs/maintenance/1.21.1迁移报告.md`。

`ItemData` 对 `minecraft:custom_data` 实施复制读取、整体写回，避免不可变组件共享导致不同ItemStack互相污染。`CarrierRepository` 先比较组件引用；组件替换后重新验证内容，不使用已经失效的运行缓存。原聚合脏状态/提交规则保持，待机不重新编码JSON。

`NativeStackCodec` 负责模组私有 `Carrier` 字段中1.20原版物品记录的DataFixer升级，当前数据仍通过注册表感知的原版ItemStack编解码。外部损坏数据继续原文保留并停用，绝不回退生成满状态新载体。世界SavedData及方块实体适配1.21的HolderLookup.Provider；内部版本不变。

`CircuitNetwork`、`BookNetwork`、`VisualNetwork` 使用有方向约束的CustomPacketPayload和StreamCodec，在RegisterPayloadHandlersEvent注册，当前协议 `1.21.1-3`。处理器运行在对应逻辑主线程，仍由服务器用例校验身份、所有权、槽位、距离、材料与频率。客户端提交意图，不提交权威运行结果。

`SpellDamage` 使用独立数据驱动伤害类型，继承原间接魔法的护甲/狼甲/女巫抗性等标签，额外禁用新版原生伤害自动击退。元素风和命中击退继续显式消费预算，不修改原版间接魔法标签。

批量特效改用1.21 BufferBuilder、VertexConsumer与GameRenderer绘制接口，保留世界事件观察、客户端时间线和单材质批次。静态图集、音频内容及服务器观察预算不变。验证器仅在测试源集中，正式模组不包含自动开世界或截图逻辑。


## 0.16施法表现分层

`SpellGeometry`独立计算纯表现几何，不依赖Minecraft或GPU；`SpellVisualRenderer`只提交共享图集顶点。`VisualStyles` v2原子发布阶段及元素美术样式，原创16格图集由离线脚本生成。`VisualTimeline`对完全相同的观察去重刷新，并限制冲击重触发，避免同位置透明层不断叠加；帧预算先服务命中与释放。

`SpellFeedback`按世界/施法者合并实际释放和被原版接受的伤害确认，步末只向本人发送有方向限制的`FeedbackNetwork.Pulse`。客户端`FeedbackPulse`只拥有有限本地反馈寿命，`FeedbackClient`只改变准星和渲染相机角度，不反写玩家朝向、速度或法术时刻。本地镜头及准星偏好由`FeedbackConfig`独立保存。协议升为`1.21.1-2`，玩法保存版本不变。

起阵与释放分别增加START/CAST观察；无效输出不产生假反馈。近镜头法环缩小淡化，撞墙有接触爆发但没有伤害准星。声音素材加入原创瞬态与低频主体，原28事件、空间衰减及限频不变。实现、开关和验证见 `docs/art/施法表现与打击反馈.md`。此前静态美术节中的4格描述属于历史基线，当前以本节16格为准。

## 0.17界面与资源

`WorkshopSkin`是共享静态九宫格图集的绘制适配器，统一按钮、面板和书籍的配色；不参与输入、网络或法阵状态。`WorkshopLayout`为纯布局值，由工作台控件和预览共同消费。`GlyphAtlas.wand`保留方形贴图的比例，放大预览不会拉伸法杖。

`EditorModel`换选符文时清除旧参数滚动位置；`CircuitScreen`选中符文后优先装配其设置，未选中才显示示例。输入和权限链未改变，完整参数仍先编辑草稿、再请求服务器保存。资源由`bake-workshop.py`离线生成，`bake-art.py`统一调用。32像素物品与工作台贴图、256像素界面图集随JAR发布，世界和协议版本不变。

`-Showcase`只加入测试源集中的客户端界面参考导出器，不进入正式模组。导出图使用独立示例数据，来源随宣传素材记录，不能作为连续游戏实录。验证与画面见 `docs/art/界面与美术整理.md`。

## 0.18三维法杖与独立释放能力

`WandPreview`缓存经过规则校验的27种只读显示物品；工作台、背包和世界使用相同OBJ烘焙结果。Blender源文件与制作脚本独立保留；运行时只使用NeoForge原生静态模型加载器。0.17的`GlyphAtlas.wand`保留为旧像素图集兼容绘制，当前工作台与法杖物品使用真实网格。组件注册与语义变化要求两端统一升级，协议升为`1.21.1-3`。用法与验证见`docs/art/三维法杖与施法冷却.md`。

## 0.19世界魔力场与环境供给

`ManaField`拥有稀疏单元的场量、同步扩散、耗散、有限发现余量、相位和守恒账本；`ManaNode`只拥有有限燃料账本。两者不引用Minecraft，规则经独立JSON加载并随状态冻结。`ManaFieldPersistence`严格校验NBT后才发布替换，未知版本或坏账原样保留并停用。

`WorldManaField`是每维度SavedData和已加载空间索引，固定步位于`WorldCircuits`之前；无离线补算、强加载或客户端写入。`ManaNodeBlockEntity`维护实体和携带物的燃料恢复、掉落和亮灭。节点的候选释放先经场容量接纳，再扣本地储量；拆除只保留人工节点的剩余储量，天然储量被丢弃时不会凭空重置成水晶。

`CircuitHost.ambient()`是与原供给并列的`ManaSource`能力，默认零供给。Minecraft宿主按玩家/固定块位置装配每步共享额度，多槽位和多个汲取符文共同消费同一实例。VM处理输入背压与资源复用，不调用世界、区块或静态服务器服务；纯汲取图的控制成本从环境支付，有普通输入的混合图沿用装备供给。旧图不改变供给语义。`CircuitScheduler`继续拥有唯一的宿主顺序。

场只在扩散步处理全部活动索引，数学更新上限8192单元；大场依保存的世界时间轮换批次，不引入未保存的游标。发现记录上限262144，达到上限后不驱逐已消耗区域。单元尚未发现或区块卸载时不参与交换。完整能力与限制见`docs/systems/魔力场与节点.md`。

新符文同步贯通定义、端口、求值、现场v5、蓝图、编辑分类、原创符形图集、示例和测试。节点及矿物使用原生模型和数据包世界生成；普通法杖说明隐藏重复的原版属性段，真实属性仍由部件计算。冷却底环改用有透明混合的共享RenderType，实际PNG不透明度生效。当前网络协议`1.21.1-6`。

## 实体工作台与静态模型（0.20）

`InscriptionAccess` 保存工作台位置、维度、目标身份与原持物引用。配置替换、基板安装、新增槽位和连线变更每次重验工作台、8格距离及实际持物；起停、选阵和运行开关仍为运行操作。`WorkshopService` 独立拥有组装会话，两者都不承担VM求值。

两种工作台共享轻量 `WorkstationBlockEntity`，它没有物品库存，只在服务端引用编辑目标；客户端只同步杖端、杖身、杖尾三个标识。刻阵台基板材质使用方块状态；切换材质只重建对应区域。两格桌子的主半边拥有唯一实体，副半边引用主位置；拆除联动不复制掉落。旧单格桌只在明确互动且侧面可用时展开。

Blender OBJ由NeoForge在资源加载时烘焙进原生区块模型，单张Aseprite图集共享材质。`WorkstationRendering` 只为有预览的法杖台提交一个缓存法杖模型，不逐帧构造桌面几何。法杖仍在玩家手中，离开、换持物、关闭界面或重新加载会清空预览；预览不保存法杖副本和法阵现场。空更新包也通过显式 `onDataPacket` 清除客户端旧投影。

`FixedCircuitAppearance` 以已提交聚合的第一块板派生小型外观标记，物品渲染不解码法阵。先提交聚合再写外观组件，避免组件身份变化使仓储丢失尚未提交的编辑。基板制固定阵是服务器工作台用例；0.21起先建立未发布草稿，完成非空有效蓝图后才消费一张真实材料板，交付零魔力、未起阵且保存所绘法阵的载体。

## 工作台几何修复（0.20.1）

Blender导出`assets/elementalcircuits/geometry/workstations.json`，由`WorkstationGeometry`一次加载为类型明确的桌面布局及缓存VoxelShape。碰撞按朝向和半边切分，斜面用32段逼近，避免手写整块碰撞与模型分离；此模块仅属于Minecraft几何适配，不进入法阵领域或VM。

工作台图集256×256，每个64像素区域含32像素画稿和四边16像素外延。UV按模型空间和纤维方向投影；只有基板正面使用符纹，侧面与底面使用对应材料。法杖各调色板改为16×16，保留原配色并支持四级mipmap。工作台和法杖导出统一拒绝未拆分多边形。

双格桌面的世界模型分别为`wand_workbench_foot`和`wand_workbench_head`，从同一完整模型裁切并插值UV，各自烘焙在自己的单格范围内；完整模型仅供物品显示。主半边仍是唯一功能实体。

`WandDeskPose`读取实际烘焙顶点，用下凸包寻找跨过中部的两处支撑，拟合杖端和杖尾的高度；再约束斜面、桌面足迹和单格高度。姿态按BakedModel弱缓存，资源重载后对新模型重新计算。渲染使用NONE上下文，以明确的单一变换放置模型，避免叠加物品展示角度。客户端验证对27种实际模型逐顶点检查，服务端验证八种桌面状态的真实碰撞高度。

这次改变客户端碰撞几何，协议升为`1.21.1-6`，两端需要同时更新。保存与蓝图格式未改。

## 固定阵盘与刻印事务（0.21）

工作台 `getShape` 只返回所在方块的完整边界，`getCollisionShape` 继续使用缓存的实际斜面/水晶几何。两格桌子每半边各显示一个占用格；选中轮廓复杂度不再取决于物理碰撞细节。

固定阵盘为三份静态OBJ，共用独立的256×256带外延Aseprite图集，直接烘焙进原生区块；无新增逐帧方块渲染器。`blender_mesh_atlas.py` 统一两类模型的UV与封口导出。阵盘低矮的碰撞与选中形状按朝向缓存，不再遮挡完整方块面。

`InscriptionAccess` 会话独占基板草稿、材料、目标身份和原持物引用。草稿物品只存在于服务端会话，不进入玩家库存、世界调度或持久化；编辑包新增只读 `draft` 标志，协议 `1.21.1-7`。草稿只接受保存和观察，不能起阵、换板、新增槽位或操作互联。每次请求重验工作台、距离、维度和实际持物；逐玩家步结束时失效会话也被撤销。

完成顺序为：解码与校验非空蓝图 → 使用被冻结的板材规则替换法阵 → 提交完整编码与外观标记 → 最后重验会话 → 结束会话 → 消耗一张原基板并交付。单张替换原手持槽，堆叠交付背包，满背包则掉落成品。确认包结束草稿界面；失败不消费。会话失效后旧身份不能命中新草稿；完成后重放请求也不能再次消费。取消、离开、死亡、换持物、维度切换或登出都不会交付半成品。

非空蓝图不强制包含伤害输出或输入输出对，允许玩家制作纯信号逻辑和互联模块。蓝图自身仍校验符文、类型、路线、材料边界等；现有固定法阵物品与世界实例可继续在工作台修改，保持原身份、储量和运行状态的规则。

## 阵盘贴图细化（0.21.1）

`paint-fixed-circuits.lua` 独立绘制1024×1024固定阵盘图集，每个256像素区域包含128×128有效画稿与四边64像素外延。Aseprite源分为底材、刻槽、镶线符纹、触点磨损四层；`paint-workstations.lua -fixed=true` 兼容入口转调此脚本，普通工作台图集不变。

共享导出器 `face_uv` 从物体读取 `atlas_content`，默认32保持工作台原UV，固定阵盘指定128，按新密度计算半像素内缩。只改UV，不增加顶点、面数、动态材质或逐帧渲染。三种阵盘保持原生区块静态烘焙。玩法、数据和网络协议不变。制作步骤、实机近景和回归记录见 `docs/art/法阵贴图细化.md`。

## 扩展体积形状（0.22）

`ShapeVolume`和版本化`ShapeRules`为纯领域几何；同一局部坐标规格分别由服务端`ShapeFrame`、客户端`VolumeGeometry`使用。`ShapeSpells`仅处理定位和既有奥术分包，`ElementInteractions`统一构造符合几何/遮挡/权限的接触并使用既有有限分配器。没有把地形响应复制到形状分支，也没有增加按视觉寿命攻击的持续实体。

扇面随完整视线，其他形状使用水平朝向；墙永远直立。薄墙对方块可见性采用最近表面点，避免瞄准点贴面时，相邻正面被误认为穿过目标中心。格子成员仍以中心采样确定。查询只读已加载区块，最多512个近格、128个实际接触。

新符文及缓存新形状的VM现场使用v6，旧v4/v5保持读取；接收阵的现场版本依缓存实际内容判断。网络协议1.21.1-8，新增观察种类追加枚举，不改变历史编号。新观察强制整数半径与单位法线，不能使客户端创建零半径体积。新形状禁止作为在途弹道保存。

原创静态符印由`bake-glyphs.py`单独构建；渲染在原8192四边形预算内加入短时轮廓与元素碎屑，共用一张特效图集和一个批次。`ShapeExamples`是编辑器与测试共用的真实路由示例。参数、边界、验证和截图见`docs/systems/扩展形状符文.md`。

## 稳定持杖与三维书籍（0.24）

`ItemAppearance`提供不反写的身份/部件小投影，`CircuitWandItem.shouldCauseReequipAnimation`只在换槽、换身份、换外形时要求重新装备。客户端原生手部扩展抑制稳定持杖后的原版CD高度重置，仍绘制近战挥动；原版风格物品栏遮罩独立读取每根法杖的同步冷却组件。未使用按物品类型共享的ItemCooldowns。

两类书共用Aseprite图集，Blender导出的刚体OBJ在资源加载时烘焙。`BookItemRenderer`经原生BEWLR绘制缓存部件，`BookMotion`只管理固定步动画及插值。主手、副手和当前页面三个轨道有界，选页确认触发翻页，资源重载重新查询ModelManager；世界/退出清理轨道。领域求值、存储和网络不持有动画状态。远端实体采用静态展开姿态。制作、真机截图和验收边界见`docs/art/三维书籍与稳定持杖.md`。

## 服务端策略与工程边界（0.27）

`CircuitBounds` 只定义格式和算术保护，不读取NeoForge或玩家状态。`ServerSettings` 是适配层：NeoForge SERVER配置 → 新实例的冻结规则 / 新编辑请求的准入校验。降低预算不参与恢复构造，既有法阵、场单元和在途法术不会因此被当成坏数据。

新 `Rules.BoardSizes` 是不可变的三材料规格；旧规则v1保留4/6/8，新规则v2严格要求记录。扩大图规模贯通符文/路线、VM数组、观察模型、JSON、NBT字节编码、文本码与网络文本边界。输入参数可超过节点容量，VM按节点容量背压并只对可接受的注入付费。计数/节拍采用独立整数域，资源继续受16.16安全域保护。`EditorViewport` 是纯本地视图，绘制与点击共同消费变换后的布局。

`ManaPool` 的管理余额、容量和恢复策略操作独立于 `debit`，不得伪造消费或清空累计支出。`PlayerMana` 持久化v1个人恢复覆盖，读取保存余额后再采用当前策略；降低恢复等待夹住剩余等待，不补魔力。`AdminCommands` 只在服务端权限2上下文执行，玩家选择器全部先校验；成功后保存并同步HUD。

`ManaField.reconfigure` 是显式策略变更，升级场记录v2；降低容量造成的超额进入耗散账本，累计初生量不再从当前初生规则反推。v1恢复继续执行原严格等式。`WorldManaField` 仅在显式命令时采用新场规则，活跃预算确定轮转，不加载区块。节点库存/容量保留自身冻结规则，输出上限采用当前场规则。方块扫描预算约束枚举本身，大范围采用确定格点采样；每目标仍共享有限原始魔力。

NeoForge原生配置页只在物理客户端注册；服务端不加载客户端界面类。登录后的果实提示数值另有16字节策略观察，仅在变化时发送，清理世界时清空客户端显示缓存。玩法从不读取这个显示缓存。完整键表、单位和生效范围见 `docs/systems/服务端配置与符文边界.md`。

## 有界魔力传输与书籍姿态（0.28）

`Rules` v3保存独立`manaSteps`（1–64），`TickCircuit`最初采用现场v8（0.34升级v9保留队列）；旧规则和现场纯恢复时不改语义。`MinecraftCircuitHost.prepare`在调度边界调用`CircuitAssembly.retimeMana`，通过完整现场迁移为当前服务端速度，保留每个包、控制态、计数和账本。变更标记识别新实例，后续相同速度不再重建。

每次`tick`仅注入、汲取和支付信号供能一次；控制采样只在首轮执行，随后只推进魔力。各轮保持交付→节点→发布的同步顺序，反馈有界，无进展时提前结束；发布信号、逻辑时钟、窗口和注入倒计时仍每世界步一次。`CircuitScheduler`的跨阵阶段及宿主steps=1保持，释放经过原CD许可。编译后的载荷索引、魔力出口和权重只归VM所有，不进入保存；线路运算逐成分直接计算，保留每格取整。

书籍继续使用静态烘焙部件，渲染器把封面展开到180°并压低书脊；源Blender动画与两种手持变换同步，动画不持有或修改法阵。配置、基准、迁移与实机验证见`docs/art/书籍姿态与魔力流转加速.md`。


## 事件子法阵与选择界面（0.29）

`CircuitAssembly`保存逐源槽位的`TriggerBinding`，存在派生时外层版本2；不持有世界对象。`InvocationProgram`冻结同载体蓝图与规则，`TriggeredCircuit`创建全新单次VM并按预付预算分配INPUT，运行和恢复不触及原槽位现场。引用目标必须保留入口；停供且工作台授权后才能配置。

`RecursiveSpells`归属每维度`WorldSpells`，以共享程序、根链、一次性预算胶囊和轮转任务代替递归Java调用。权威飞行体将预算拆为母体与触发两份；屏障共同吸收，碰撞/定时回调消费一次。新增任务在下一步推进，新飞行体在更后一步移动，区块卸载冻结。根强度只继承一次，子阵不接玩家/环境源、不接跨阵网络。世界法术v9包含完整子VM、供给、位置、方向、定时和链额度；缺失引用原样保留并停用，v1–v8显式空初始化。

`CircuitSelection`是与完整编辑包分离的轻量观察。`BookService`重验当前物理载体，`BookClient`提供Z/X和R；`SpellWheelModel`纯几何、Screen处理输入、Renderer负责绘制。迟到回复不能重开界面。管理页用独立槽位卡片、折叠基板和固定保存栏；配置走带请求令牌的既有服务端命令，不由渲染反写。

网络协议1.21.1-13。默认深度4/激活64/窗口120、活跃链128/任务128/工作容量16384、每步推进32个VM；调度预算轮转，容量不足拒绝新事件。完整边界和验证见`docs/systems/法阵管理与递归施法方案.md`，实际GPU工具为`-RecursionSmoke`。


## 只读探测与异步勘测（0.30）

`ProbeWandItem`通过原生使用管线调用`ProbeService`；右键事件只为探测杖禁用方块交互，避免刻印、充能和供给开关被误触。`ProbeReports`返回脱离实体的`SurveyReport`，不调用场discover，不操作原VM。节点/法阵诊断改由探测杖承担，水晶装填仍为正常功能操作。

`SurveyArea`拥有三维球体与区块候选；纯应用层`NodeSurvey`拥有增量统计、异步完成收集、失败/缺失分类和停止状态，不拥有线程或文件。`SurveyChunkReader`在服务端优先读取已加载区块的实体位置并复核方块；其余走原生异步存档读取，以纯NBT段调色板解码统计实际天然节点。先检查区域文件存在性，避免原版read对缺失.mca执行CREATE；不加载区块，不按生成随机数预测。

每维度默认2任务，共享每步16个读取启动预算，每任务最多16个挂起读取，超时2400逻辑步。轮转公平；取消不取消引擎共享IO，只放弃观察引用。未生成/未完成、损坏或超时均明示部分覆盖，不能当成完整的零节点；读取具有时间跨度，非整个范围的原子快照。

`ProbeNetwork`仅单向发送有界报告、请求身份与维度；客户端Screen接收匹配进度，Renderer纯绘制，关闭后的进度及跨维度消息不打开界面。新协议1.21.1-14，旧世界无需新增持久化迁移。静态探测杖模型复用既有材质调色板，原生模型烘焙；验证入口为`-ProbeSmoke`。详见`docs/systems/探测杖与天然节点勘测.md`。


### 触发条件的明确选择（0.30.1）

客户端`TriggerDraft`允许未选条件，合法`TriggerBinding`仍要求非空类型。未完成草稿不发送、不保存；新配置不预选命中，旧配置恢复原值。`TriggerCondition`接收权威事件并返回WAIT/COUNTDOWN/FIRE，`When`各类型提供策略，服务端一次性提交和预算调度不依赖具体类型。新增类型需实现策略与显示文本；涉及新参数/运行状态时显式升版，不允许未知类型静默降级。保持现有程序集v2、冻结程序v1、世界法术v9及网络1.21.1-14不变。


## 同基板叠阵（0.31）

`PlateLayers`保存同一基板的不可变派生定义和内部触发边；`CircuitAssembly`仅调度主阵VM，快照v3与变更标记纳入阵层。`LayerRules`按配置初值和材料增长公式给出深度。新冻结程序v2只引用当前基板，本地根编号恒为1，物理槽编号不混入事件运行。旧跨槽数据保留而不用于新发射，旧冻结程序v1继续恢复。编辑网络当前1.21.1-16携带明确槽位/阵层/令牌，草稿按完整地址隔离；独立`LayerScreen`负责关系子界面。详见`docs/systems/同基板叠阵与编辑导航.md`。


## 魔力酿造与部件贴图（0.32）

`ManaRecoveryRules`是不依赖Minecraft的定点倍率规则，`ManaRecoveryResources`加载独立v1 JSON。`ManaBrewing`只注册原版MobEffect、Potion和酿造配方，不引入自定义瓶子、计时器或网络包。玩家效果的强弱覆盖、持续时间、牛奶清除、喷溅/滞留与NBT保存由原版处理。

`PlayerMana.get`每次从服务器/玩家管理策略读取基础恢复值，再按当前原版效果计算有效速度。倍率不写回基础策略；状态读取不推进tick。现有20Hz魔力槽负责等待、余数和恢复，药水不补满、不增加容量、不清除消费账本。配方时长来自版本化JSON，`manaPotion.bonusPerLevel`为服务器可配置增益。

`art/aseprite/parts/`保存29份可编辑分层源文件。`tools/artwork/paint-plates-parts.lua`在Aseprite批处理绘制并导出；`tools/artwork/bake-wand-palette.py`重新导出已绘制材质并生成静态粒子图集，缺源文件明确失败。`tools/artwork/unwrap-wand-materials.py`离线为27个原有OBJ按部件和面方向生成UV，保持几何、组、材质和面序；Blender导出流程末尾调用同一UV步骤。运行时仅加载PNG与OBJ，不绘制纹理、不重算法杖UV。


## 元素伤害与统一反应（0.33）

`DamageAffinity`提供稳定资源后缀，12个`ec_damage` DamageType JSON由原版数据包注册，`SpellDamage`按服务器当前RegistryAccess构造伤害源，不能缓存跨世界Holder。`ElementalDamageSource`保留只读逐元素伤害及归属UUID。

`ElementalCombat`接收不可变魔力、强度、目标状态快照与版本化`ElementalCombatRules`，纯计算抵消、状态条件、逐成分伤害和状态意图。规则使用定点运算，伤害预算按比例缩放，大数乘除使用精确中间值。`ElementalCombatAdapter`重验权限，过滤对应免疫，处理原版霜弱点，调用一次原版hurt，成功后提交状态；原版受击无敌帧不重置。

`CombatEffects`只注册潮湿，沿用原版计时、NBT、同步和清除。已有冻结/燃烧/致盲等状态不另建数据库。反应显示复用`CombatReactionFeedback`→`SpellVisuals`既有有界批次，每命中最多一条主要反应，替代普通命中动画；玩法不等待特效、声音或网络回执。详细规则与混合附魔保护边界见`docs/systems/元素伤害与反应.md`。

## 元素队列（0.34）

`Mixture` 同时拥有成分账本与有序片段，`TickCircuit` 拥有本阵单调接收计数；`Packet.merge` 稳定归并接收序号。所有预算变换选择原队列子序列，禁止重建向量丢弃顺序。完整现场v9保存计数和队列；独立包v2、世界法术v10、递归表v2，长包经 `JsonNbt` 的有界UTF-8字节保存。

`ElementReactionRules` 定义相克关系，`ElementReactionQueue` 是纯FIFO抵消器；`ElementalCombat` 先抵消，后按幸存顺序推进虚拟目标状态。`ElementalCombatAdapter` 仅在一个原版伤害调用被接受后按序提交状态。世界作用在有限目标分配前抵消，方块按幸存队列选择一次原子转换。规则、迁移与限制见 [元素反应队列](docs/systems/元素反应队列.md)。


## v0.35 成本与返还边界

`CastingRules`冻结参数损失、占格成本、缓存/在途衰减、元素返还率；`CastBudget`先解析实际参数再高精度报价，`ShapeFootprint`只计算逻辑几何。`CastContext`由宿主注入，输出的`SpellSpec`冻结玩家法强，领域层不读取原生属性或服务器配置。旧载体在明确调度边界升级Rules v4，保留完整运行现场。

`Mixture.Portion`同时保存到达顺序和`ManaOrigin`；数量扣除必须匹配成分和来源。`ManaSource.preview/draw`使有限预付子阵也能保留多来源，报价无副作用，支取失败无变化。新版子阵不缩减固定输入。

VM只生成持久化`RefundTicket`，不直接操作玩家。宿主将票据交接`WorldManaRefunds`后确认；玩家、固定装置和场格点在自己的持久化单元中保存累计`RefundReceipts`，供重试防重。离线/满槽/卸载保持待付，不强加载。每步工作预算和保留凭据预算可配置；检查起点由已保存的游戏时间推导，无未保存的调度游标。跨玩家、区块和SavedData突然断电时的强事务不在本版保证范围内。

几何适配器统一携带`ContactMagic`。元素抵消、附加效果分账及最终原生hurt边界共享一次命中；`HitModifiers`只提交已接受的计划。`WandWear`为纯分段函数；原生属性注册、计时和装备耐久写入留在服务器。

格式：VM v10、元素队列v2、Packet v3、WorldSpells v11、RecursiveSpells v3、TriggeredCircuit v2、ManaNode v2；网络1.21.1-17。公式、配置和迁移细节见`docs/systems/施法成本与魔力动力学.md`。


## 0.36 装备承载

`WizardEquipment` 注册原生护甲材质、四件装备与戒指；`WizardArmorItem` 用原生 Attribute modifier 提供法强/额外容量/固定恢复。`ManaPool` v2 将永久容量和装备额外值分开，旧 v1 显式零装备加成迁移。`CuriosEquipment` 是唯一的饰品库存适配器，排除装饰槽。

`EquipmentCasting` 负责实际穿戴身份、槽位选择和 MANUAL/HURT 激活；触发配置版本 1，与法阵输出方式分开。`EquipmentNetwork` 只接受意图，服务器复核物理所有权。装备通过既有 `WorldCircuits → MinecraftCircuitHost → CircuitScheduler` 推进，没有第二个 VM 或独立供能池；`CastingEquipment` 隔离法杖部件与装备冷却。卸装后禁止新增供给/释放，普通背包残余照常衰减。

`SpellSpec` / `CastContext` 的反击来源标记经过包、二次派生和递归现场保留，最终转换为 `ElementalDamageSource.reactive`；受击起阵在原版实际伤害 Post 阶段判定，拒绝反击来源，从因果上关闭反击环。

`EquipmentWheelScreen` 负责输入和网络，纯角度选择在 `EquipmentWheelModel`，表现留在 `EquipmentWheelRenderer`。`WizardArmorRendering` 只在资源重载时烘焙 Blender 导出的骨骼/方盒 JSON，运行姿态和附魔渲染由原版处理。


## 0.40 只读指南与可选Patchouli适配

`CircuitGuideItem`只负责原生使用动作，不参与载体仓库、运行时或魔力账本。`GuideClient`选择存在的阅读后端；`PatchouliGuideClient`隔离全部可选API类型，`GuideBookScreen`复用原版阅读器并按当前字体分页。两种后端都不执行命令、不写入法阵。

`tools/artwork/bake-guidebook.py`是双语内容源，生成标准Patchouli资源、原版阅读器静态内容和原创16×16封面。分类与配方仅引用已有注册项，原版配方管理器拥有合成规则。指南书不新增网络协议或存档版本。独立客户端、独立服务器和完全移除Patchouli的运行路径分别验证，测试夹具不进入生产包。


## 0.41 包结构与手持指南模型

领域层按 `circuit`、`mana`、`casting`、`combat`、`equipment`、`logic`、`book`、`survey` 分类；服务端按宿主、施法、世界效果、魔力、装备、工作台和探测分类；客户端按页面、输入、HUD、注册和表现分类。配置、编解码、静态规则加载与兼容分别位于 `adapter/config`、`codec`、`resources`、`compat`。具体入口和开发命令见 [工程结构与排版](docs/maintenance/工程结构与排版.md)。

指南书使用 NeoForge `separate_transforms` 在四个手持显示上下文选择静态 OBJ，在其余上下文保留平面模型。Blender 原稿、Aseprite 图集和运行资源独立存储，资源加载时烘焙，手持渲染不创建新网格。页面阅读、物品使用、施法逻辑和持久化没有新增耦合。

## 0.42 抵消规则与跨载体选择

原生适配器通过 `ElementalCombatResources` 加载反应表 v2，反相奥术加入其余 15 种元素成分的 FIFO 抵消关系，纯净成分除外。`ElementalCombat` 不再将剩余反相奥术转换为伤害；v1 兼容构造器仍冻结。`SpellPayloads` 将含反相奥术的混合载荷保留到接触，禁止提前拆出穿透支路或预支光照。反应不新增可变全局状态。

`BookSelection.Choice` 用 `(carrier UUID, local slot)` 标识选项，`CircuitSelection` 为最多两载体、八条目的不可变观察。`CastingEquipment.select` 在服务器校验实际主副手和槽位，`SpellSelectionRepository` 仅在法杖保存选中来源；完整法阵仍由各自 `CarrierRepository` 独占，不建立镜像 VM。已有蓄力状态机同时校验来源与槽位，改变来源取消待释放手势。

轮盘以主手法杖 UUID 绑定会话，并记录副手物品 UUID；换任一来源均关闭。选用请求携带来源与槽号，服务器拒绝失效来源。`SpellWheelModel` 支持 1–8 扇区，`SpellWheelRenderer` 只消费观察并标明杖/书。新增 `SelectedSpellSource` 为可选物品数据，旧物品回落到本杖；网络协议为 `1.21.1-20`。详细边界见 [反相奥术与联合选阵](docs/systems/反相奥术与联合选阵.md)。

## 0.43 基板保护边界

`BoardSafety`是纯公式与元素烈度策略，`BoardCondition`是逐槽位的物理耐久、熔毁状态和供给游标，独立于冻结蓝图与杖体ItemStack损伤值。程序集v4保存完整状态；旧记录在仓库边界补齐健康基板，保留历史VM并初始化供给游标，不追溯磨损。重存蓝图保留健康记录，更换物理材质才建立新记录；修复意图必须经过服务器工作台会话和材料校验。

`CircuitProtection`是同步推进的保护接口。`TickCircuit`在实际注入后、执行和输出前调用；`CircuitHost`提供槽位保护，调度器不持有Minecraft世界或爆炸类型。宿主先更新并提交一次性熔断状态，再调用`BoardMeltdown`原生适配器。清空魔力计入loss，已欠来源的返还凭据不回收、不重复耗散。断供的基板拒绝起阵和接收。

客户端仅消费`BoardStatus`小型原生观察和管理页只读投影，不为绘制损坏状态加载VM。27个失效模型复用原有几何，裂纹暗化贴图在构建前静态生成。网络协议`1.21.1-21`。公式、配置和递归冻结边界见[基板承载与熔断](docs/systems/基板承载与熔断.md)。


## 0.44 固定法阵控制与观察

`FixedCircuitControl`统一方块和调律杖的起停校验。`FixedRelationSight`只读取已加载对象构建有界同步视图，`RelationNetwork`与编辑器协议独立；`FixedRelationRenderer`负责失效回收和批量画线，不加载或修改VM。`MonocleRendering`独立烘焙头骨局部模型。观察不写存档，旧物品数据无需迁移。


## 0.45 魔力生态与浮光节点

`ManaEcology`独立注册实体类型与原版生成判据，读取已加载节点与已存在的场单元；每只原版史莱姆每20tick采样一次，进度由原生实体持久数据保存。`ManaSlime`继承Slime原生AI与分裂，客户端独立皮肤渲染。`InstantMana`适配凝胶与瞬时效果到`ManaPool.restore`，新增能量不改来源返还历史。

浮光节点是`ManaNodeBlockEntity`的天然节点形态，保留原有ManaNode与ManaFieldRules快照格式、自然恢复和场调度；容量与输出初值仅于首次初始化冻结。`ManaEcologyRendering`烘焙生物与渲染相机朝向光晕，模型不参与碰撞/供能判定。世界生成与掉落由原生数据包资源控制，`SurveyChunkReader`的已加载和离线调色板路径统一纳入浮光节点。旧节点与玩家存档无需迁移。


## 0.47 输出效率与双槽观阵镜

`EffectScale`是冻结的整数比例，独立于法强与来源魔力。`CastBudget`先计算名义参数和成本，再确定真实运输量；接触适配器在反应与分配前折算一次效果。`SpellSpec`、包编解码与世界法术v12保存此比例，二次派生保留，递归资金只认真实Mixture。光弹照明以效率折算报价并反向上取整支付，不能预支未付零头。

`CuriosEquipment`统一真实头部饰品查询和附魔属性修饰身份；观测、元素防护与维修共用此边界。`CircuitMonocleItem`同时实现原生护甲和Curios装备契约，`MonocleRendering`在两种路径复用同一头骨模型；装饰槽只参与外观。`SpellAttributes`在原生属性清洗边界处理非有限值，玩家槽补满后恢复状态可完整往返。详细公式与验收见[数值审查与输出效率](docs/systems/数值审查与输出效率.md)。

## 0.48 符文矢量源与静态渲染

`art/inkscape/runes.svg`统一70个符形；`bake-glyphs.py`调用本地Inkscape离线导出主图集和三档指针，派生只读索引与几何契约。`GlyphAtlas`保留共享纹理批量绘制。`PointerBitmap`只负责缓存解码、裁切和染色，不再画线；`NativeEditorCursor`仍缓存OS句柄，移动时不重建纹理。SVG路径不进入VM、网络或世界状态。工作流见[Inkscape符文矢量化](docs/art/Inkscape符文矢量化.md)。

## 0.49 查询与活动索引

`ItemData.section`提供独立小节副本，读方不得取得NBT内部可变对象。`TickCircuit`只在创建时建立接口编号索引，推进仍依照原节点顺序。`WorldManaRefunds`将持久去重表与派生未结清索引分开，完成记录不再占投递预算，离线来源保留；不增加持久字段。`VisualTimeline`按逻辑变更发布不可变观察列表，同一逻辑步多帧读取复用。测量、修复与剩余工程问题见[代码质量与运行开销审查](docs/maintenance/代码质量与运行开销审查.md)。

## 0.50 物料端口与红石采样

`MaterialPorts`是平台无关的方向修饰，随`SpellSpec`合流、默认值补齐、效果缩放和在途包保存；同维度冲突拒绝。固定`MinecraftCircuitHost`才授予载体UUID绑定，接触时`MaterialOperations`通过所有权复核、已加载相邻方块和有侧ItemHandler访问实物。域内魔力包不携带ItemStack，也不提前提取库存。历史包缺少该字段时迁移为NONE。首期递归子阵不授予新的外部物料绑定。

`CircuitScheduler`在互联信号交付后调用`CircuitHost.sampleExternalSignals`，再统一推进。红石感应使用既有独立驱动数组和线路时序，不混入跨阵SIGNAL_RECEIVE地址。无锚点宿主采样为低电平，不自动改起停状态。`ElementInteractions`沿用同一魔力分配与元素反应流程，`MaterialOperations`只执行通过预算后的拆解/构筑事务；原生权限、破坏/掉落/放置事件和库存提交复核留在适配层。

网络协议升级为`1.21.1-22`，要求两端共同升级。73个符形继续由Inkscape离线导出，指南两阅读器共用静态双语源稿。首期范围、成本和配置见[物料与红石自动化](docs/systems/物料与红石自动化.md)。

## 0.52 分流、延时与观察

`Route.sourcePort`明确源出口，默认0兼容历史线路。蓝图4校验出口与载荷匹配，编辑器具名出口直接开始布线，重布线与预览保留编号。`FILTER`按成分和极性划分资源后在端口内均分，保留来源与到达顺序；`SELECT`按有效信号择一出口，缺少承载出口则阻塞。新协议统一先采样控制再搬运魔力，旧协议保留原采样时刻。

`DELAY`仍使用只传信号的时序契约，其完整`RuneLogicState`保存变化队列及本地运行时间。不可变双栈`SignalQueue`在状态之间共享节点，摊销常数时间推进，序列化为扁平列表。新蓝图现场13拒绝非法时间、队列或混入旧协议的新状态。

`ConnectionEffects`增加锚定、筛选和联系控制编号，所有合流、复制及编解码保留这些字段。`WorldConnections` v2保存锚点；旧v1明确无锚点。信号解除按联系符文及所在阵寻址，VM和宿主都拒绝高电平重锁。`WorldProbe`仅观察已加载世界，宿主按世界步合并相同查询，沿现有外部信号接口注入结果。

网络协议为`1.21.1-24`，87个静态SVG符形、31条双语手札共用源稿。规则、公式和首期边界见[分流、时序与世界观察](docs/systems/分流时序与世界观察.md)。

## 0.51 联系与空间参数

`SpellSpec`增加独立的`ConnectionEffects`和`SpatialParameters`值类型。联系是施法方式，施力、约束、交互是可组合效果；不绑定具体几何。旧包缺少这些字段时显式初始化为空，所有复制、合流、报价和编解码保留维度。`INTERACT`通过既有线路时序采样信号，采样电平随实际魔力运输，出口不按渲染帧触发。

`MagicCircuit.Cast`带实际输出符文编号。宿主将联系输出交给独立的`WorldConnections`，其身份为载体UUID、物理槽位、出口编号；每个世界步重新提供源姿态和供给权限，不能凭存档或余额构造活动源。持久状态包括目标、参考距离、已付额度、强度与交互边沿，独立SavedData v1不改旧世界弹道格式。反应沿用FIFO，物理额度不可回流到法阵。`ConnectionBudget`与`ConnectionMotion`分别负责纯资源支付及冲量约束；原生射线、碰撞、交互事件和保存适配留在服务器边界。第一期联系由主阵的真实出口维持，不创建递归投射物。

`SupplyMode.gesture`仅对显式持续的联系法阵保留配置供给，其他手势仍为单次。再次右键停止联系且不在松手时重启。费用及并发预算来自服务器`contact.*`，世界步中依稳定顺序逐条结算，多联系共享单实体冲量预算。

`ShapeVolume`与`ShapeFootprint`共同读取连续张角，足迹缓存键包含张角；`SpellVisual`批量消息携带同一参数，外沿和元素流使用同一几何。偏转、俯仰在散布之前应用，联系方向不散射。协议升为`1.21.1-23`；静态Inkscape图集扩为81个符形，双语手札共29条。配置、公式与首期边界见[联系施法与空间参数](docs/systems/联系施法与空间参数.md)。
