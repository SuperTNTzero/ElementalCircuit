# 数值审查与输出效率

0.47.0 · 2026-11-03 · Minecraft 1.21.1 / NeoForge 21.1.265

本次修复针对实际结算和状态恢复，不调整标准阵的默认参数、材料承载量、基础伤害及玩家成长上限。观阵镜可放入原版头盔槽或 Curios 头部饰品槽；短镜腿从镜框侧边向后绕到头侧，饰品佩戴允许与巫师帽共存。

## 成本、运输量、效果量

原实现把实际支付的魔力和名义作用量视为同一个量。法袍减免或玩家基础魔耗属性令成本低于作用量时，输出仍尝试取出完整作用量，导致支取越界。现在分开保存三个量。

记 E 为名义作用量，P 为法强，k 为法强成本指数，m 为玩家基础魔耗，r 为减免百分数，N 为形状逻辑计格，c 为每格成本，η 为参数保留率。trunc 表示最终截断到 1/65536。

```text
μ = P^k × m × (1−r/100)
C = max(1/65536, trunc[(E+cN)×μ/η])
B = min(E, C, max(1/65536, trunc[E×min(1,μ)]))
输出效率 = E/B
```

C 是成功释放时实际消费的总量，B 是其中进入投射物或其他输出的真实魔力，C−B 进入成本损耗。名义效果仅在接触结算前按 E/B 折算一次；伤害再按杖端强度、玩家法强和现有元素规则计算。盾牌容量和施法反馈同样采用名义效果。

例如名义作用量为1，基础魔耗0.2、减免80%、法强1时，μ约为0.04。投射物携带约0.04的真实魔力，接触仍产生1单位的名义效果；水源创造、反应和附加效果不会随折扣缩水。形状与参数成本另计。所有中间比例使用整数比值，混合元素保留实际到达顺序和来源，分配零头按保存顺序处理。

效果折算不能用于魔力返还、汲取或递归供给。派生胶囊只能从真实支付的 B 中预留预算；运输与法阵账本继续满足“供给＝当前持有＋损耗＋已交付＋已返还”。输入仍先付固定输入量，结算后按来源返还未使用量，所以瞬时扣除和最终净支出可以不同。

世界法术现场升级为 v12，保存折算比。v1–v11 缺少该字段时明确采用1:1；旧协议伪装携带非1:1折算会被拒绝，保留原始数据。客户端、服务器需同步更新模组。

## 玩家属性与魔力恢复

- 法强默认1，范围1–16；基础魔耗默认1，范围1/65536–16；魔耗减免默认0%，范围0–80%。容量、回复装备加成默认0，范围0–65536。
- 五项属性在原版属性清洗边界处理 NaN/无穷值，回退到各自默认值。原版对 NaN 取最小值的行为会把异常基础魔耗变成极低成本，因此不能只在读取清洗后的数值时检查。
- 瞬间回魔恰好补满时，恢复等待和余数归零；部分补充仍保留消费后的等待。原实现补满后留下等待，产生不能重新载入的玩家槽现场。
- 魔力维修遇到已损坏的玩家槽时停止此次维修，保留原始槽记录，由正常玩家魔力更新路径报告；不把玩家槽错误标记成所有装备损坏。

容量加成不自动补满，恢复仍采用“固定回复（含药水倍率）＋容量百分比”。永久容量、装备加成、支出/返还账本继续分别保存。

## 耐久、附魔与观阵镜

杖体磨损仍采用现有强度/频率分段平方公式。强度使用名义输出作用量；频率在已有释放记录时使用真实释放间隔，同一拍多次释放按最小1拍计。首次释放采用包含迅咒附魔后的部件冷却估计。修复了用基础冷却钳住实际间隔、导致高速施法少算磨损的问题。创造模式仍免磨损。

法袍部件和观阵镜明确加入魔法装备/元素防护附魔标签，修复自定义护甲未进入原版护甲标签而无法接受防护附魔的问题。头部饰品的属性修饰使用槽位独立标识；元素防护与魔力维修也检查实际佩戴的观阵镜。装饰槽只显示外观，不提供观测或附魔效果；可见开关仅控制渲染。
