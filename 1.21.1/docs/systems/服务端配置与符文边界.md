# 服务端配置与符文边界

2026-11-01 · 0.27.0 · Minecraft 1.21.1 / NeoForge 21.1.265 / Java 21

本版把符文参数、服务端工作预算和保存格式的安全边界分开。玩家不需要等级、成就或扩容果实来解锁符文数值。玩家当前魔力决定能否支付输入，而不是决定编辑框允许填写什么。材料仍决定格盘规格和线路损耗。

## 边界审查与修改

| 项目 | 原实现 | 当前实现 |
|---|---|---|
| 输入/汲取数量 | 0.25至节点容量 | 1/65536至65536；不绑定玩家容量。输入每次最多注入节点容量，缓存不足背压等待；汲取按空余容量截取 |
| 作用量 | 64 | 65536，仍只能输出真实持有的魔力 |
| 计数阈值 | 1024 | 2147483646，整数 |
| 节拍周期 | 1200逻辑步 | 2147483646逻辑步，最小2 |
| 持续注入间隔/单次窗口 | 1200逻辑步 | 新法阵由配置指定，最大2147483646 |
| 符文/线路 | 各64 | 服务端配置，默认4096 / 8192 |
| 单线路路径 | 128格 | 服务端配置，默认4096格 |
| 符文编号 | 1024 | 正整数编号；到int上界后拒绝新增，不回绕 |
| 分流权重 | 1000 | 每项1000000；长整数求和，逐成分分配守恒 |
| 格盘半径 | 木4/黄铜6/水晶8写死 | 新板分别配置，默认仍4/6/8；格式最大128 |
| 射程/半径 | 64 / 8 | 服务端默认256 / 16，可提高至1024 / 32 |
| 分裂、连锁、弹跳 | 2–4 / 1–4 / 1–4 | 服务端默认最多32，可提高至64；分裂最少2 |
| 灼烧/迟缓 | 最多5秒 | 服务端默认最多3600秒；实际效果仍支付魔力 |

65536魔力是现有16.16资源运算的安全域；4096符文、8192线路、4096路径格、128格盘半径等是本版格式/工程保护，不代表角色成长等级。蓝图原文还有2 MiB、运行现场16 MiB的独立字节保护，复杂路径可能先触及文本预算。不能将配置提高解释为无限内存或无限运算能力。

大格盘支持画布滚轮缩放、中键拖动平移、Home复位；目录和设置栏滚轮仍用于各自滚动。绘制与选格共享同一个视图变换，格盘背景只枚举视窗内的格子。扩大格盘不会改动线路长度、损耗或邻接规则。

## 配置入口

在游戏的「模组 → Elemental Circuits → 配置」进入 NeoForge 原生配置页。单人世界内可编辑服务端项；远程服务器由管理员调整。全部服务端项也可通过 `/ec config` 列出，支持补全、查询、修改和恢复单项默认值。

```mcfunction
/ec config
/ec config get circuit.maxRunes
/ec config set circuit.woodRadius 16
/ec config set spell.maxRange 512
/ec config set spell.maxRadius 24
/ec config reset spell.maxRadius
```

文件名为 `elementalcircuits-server.toml`。NeoForge 默认从实例/服务器的 `config/` 加载，世界的 `serverconfig/` 可覆盖；优先通过配置界面或指令修改当前生效文件。默认文件可复制到 `defaultconfigs/` 用于新世界。配置类型和覆盖位置参见 [NeoForge 1.21.1 官方文档](https://docs.neoforged.net/docs/1.21.1/misc/config/)。

指令使用普通魔力单位；管理魔力指令要求数值能用1/65536精确表示，例如12.5、0.25。TOML中的魔力数值按最近的定点单位量化。整数参数拒绝小数。

## 玩家魔力指令

根指令为 `/elementalcircuits`，简写 `/ec`，全部要求权限等级2。玩家参数支持在线玩家名和选择器，下面的 `@s` 代表自己；控制台使用玩家名或 `@a`。

```mcfunction
/ec mana get @s
/ec mana capacity @s 2048
/ec mana set @s 512
/ec mana add @s -12.5
/ec mana refill @s
/ec mana regen @s 8
/ec mana delay @s 20
/ec mana resetRecovery @s
```

- `capacity` 设置容量，不补满；降低容量会夹住当前数量。管理员容量可以超过果实成长上限，最大65536。
- `set/add` 调整当前魔力，越过0或容量时拒绝；`refill` 明确补满。
- `regen` 是每秒恢复量，0关闭恢复；`delay` 是消费后的等待逻辑步，20步为1秒。
- `resetRecovery` 清除个人的恢复速度/等待覆盖，重新跟随服务端默认值，不重置容量、余额或消费历史。

操作会立即更新HUD，个人覆盖为版本化玩家数据，退出、重新进入和死亡复制后保留。修改容量或恢复策略不会擦除历史支出。多玩家选择器先校验全部目标，再修改；原始魔力槽损坏时继续保留原数据并停用供给，不通过管理员查询暗中补满。

| 场性能 | `field.storedCellBudget` | 默认262144，最高1048576；到限停止发现新单元 |

提高数量预算不消除真实魔力成本、材料损耗、世界交互权限或加载区块要求。范围方块扫描采用确定的均匀格点采样；超出预算的大体积不会遍历所有方块。被选目标共享原有魔力，不按目标或子弹复制。降低准入预算不破坏既有保存，只限制后续编辑；降低活动投射物/场记录预算也不会删除旧对象或旧单元。预算不是自动性能检测，需要按机器表现调节。

组合约束仍保留：例如光束不接受半径、部分体积不接受派生修饰、与门须等待两路。此类规则是符文语义，不是角色条件。

## 魔力场指令与规则迁移

```mcfunction
/ec field get ~ ~ ~
/ec field set ~ ~ ~ 64
/ec field add ~ ~ ~ 8
/ec field applyConfig
```

`get/set/add` 面向当前维度中坐标所在的8格单元，仅接受已加载位置；修改还要求单元已经被节点/汲取发现，不强制加载区块或凭查询创造初生魔力。`set/add` 进入注入/汲取账本，超容量或负余额拒绝。

场的容量、初生量、扩散、衰减、输出和汲取参数在维度中冻结。配置变更后，当前维度用 `field applyConfig` 显式采用新规则：

1. 旧单元余额保持；新容量变小时，超额计入耗散。
2. 初生量只影响之后发现的单元，不重填旧单元。
3. 节点原容量、库存、水晶充能规格保留；节点单步输出跟随当前维度的场规则。
4. 场记录显式升为v2，保留修改前累计初生量，保存后继续按完整账本验证守恒。

容量、初生、汲取、节点输出等必须满足相互约束，例如初生量不能超过单元容量、水晶量不能超过人工节点容量。指令在持久化前校验组合，失败回滚。手工文件出现冲突组合时，新实例使用原资源默认组并记录错误；显式场应用拒绝无效组合。需要同时改多个相关项时先调低流量/初生量，再降低容量。
