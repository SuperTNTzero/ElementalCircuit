0.47 数值修订：折扣后的成本、名义效果与实际运输量分开结算，见[数值审查与输出效率](数值审查与输出效率.md)。

历史版本：0.35.0。当前0.37.0的低损耗、准备时间和专用存储覆盖规则见 [标准状态与专用储魔](标准状态与专用储魔.md)。

本轮按用户确认实施：参数的**损失比例**降为旧值的1/100；失败按当前元素的不同返还率退回**原供给源**；法强乘伤害，魔耗乘法强的可配置指数次方，指数初值1。旧公式保留在《关键公式与变量关系》中，已标记为0.34历史记录。

## 1. 一次施法的顺序

1. 输入符文按设定的固定数量注入，多个入口分别计费。先报价、后原子支取；玩家槽不足时停止此次供给，不能部分支取。
2. 转化、线路和自然耗散仍消耗真实资源，所有片段保留供给来源和到达顺序。
3. 到输出时，先补齐缺省方式、形状、射程、半径和精度，再计算完整成本。
4. 到达量足够：支取成本，输出指定作用量；多余量进入本阵储备，继续快速衰减，可供下次注入复用。不会在同一轮将零头反复判为新一次失败。
5. 到达量不足：该批施法失败，不追加扣玩家魔力，也不靠等待合并下一批来凑预算；存活部分按元素返还率生成来源凭据。前面已经耗散的量不返还。
6. 投射物接触目标时先按实际到达队列反应，剩余量统一分账、计算元素和附加效果；一次原版hurt接受后才提交效果。

因此，输入量、目标作用量、法强和最终伤害是四个不同变量。降低作用量符文的数值，可以在相同固定输入下支持更大的形状或更高法强。

## 2. 单位与舍入

核心资源仍使用16.16定点，`F=65536`，显示值为原始整数除以F。参数范围、容器边界和性能预算仍检查。

- 精度输入支持0到1之间连续小数，如0.1、0.3333333333。输入边界先检查范围，再按HALF_UP量化到1/F；不再要求十进制乘F后恰好为整数。
- 精度仍表示**散射幅度**：0最准，1最散。除数对精度连续变化，不再分成四个台阶。
- 成本计算用BigInteger保留中间乘除精度，最后一次除法后向零截断。
- 原先`Q × floor(F / D) / F`改为`floor(Q / D)`，大除数不再让保留率提前变成零。旧执行策略也修正这一算术问题。
- 线路和自然衰减仍是逐次定点截断，最小一单位的零头最终会消散，不保留隐藏小数。

## 3. 默认参数和成本公式

记：I为固定输入，Q为到达输出的量，E为目标作用量，P为玩家法强，k为法强魔耗指数，N为形状逻辑覆盖格数，c为每格成本，s为参数损失倍率。

未配置时，E=1、方式=范围、形状=球、射程=12、半径=2、散射幅度a=0.125；显式配置同值与缺省值收费一致。光束不配置半径；盾牌和扇形不使用独立射程。爆裂半径仍按已有兼容规则解析。

参数除数：

\[
D=\begin{cases}
\max(1,R)[1+4(1-a)],&\text{指向法术}\\
1,&\text{范围法术}
\end{cases}
\]

范围法术没有使用射程或弹道散射，所以这两项不收费。半径的旧立方罚项由统一形状成本替代，避免重复收取体积成本。

旧参数损失比例为`1−1/D`，现在：

\[
\eta_p=1-s(1-1/D),\qquad s_0=0.01
\]

例如原本损失90%，现在损失0.9%，保留99.1%。**不是将保留率除以100。**

输出所需成本：

\[
C=\operatorname{trunc}_{1/F}\left[\frac{(E+cN)P^k}{\eta_p}\right]
\]

- Q≥C才释放，交付E；`C−E`计入成本耗散。
- Q<C则该批失败并按下面的规则返还Q的部分成分。
- `Q−C`是本阵储备，并非额外一发法术。
- P的原生属性范围1–16，k配置范围0–4，缺省P=1、k=1。固定装置使用中性P=1。
- 已有转化、基板、线路和信号费用保留；参数损失缩减不会免除这些成本。

近似例子，不计前级传输：半径2的范围球N=33，c=0.002，E=1，P=1，成本约1.066；相同法术P=2、k=1时约2.132。12格指向光束a=0.125，D=54、N=12，成本约1.034；P=2时约2.068。实际值还受1/F量化影响。

## 4. 形状如何计格

N是以法术中心和局部轴为基准，落入现有几何内的**整数格点数**。它表示逻辑影响体积，而非本次真的打中了多少非空气方块或生物。空地和实心墙不会改变相同法术的报价，不能靠目标密度绕过成本。

所有形状共用`cN`，初值c=0.002魔力/格，配置`casting.shapeCostPerBlock`。

| 形状 | 逻辑计格 |
|---|---|
| 球 | 整数x²+y²+z²≤r²；r=2时33格 |
| 光束 | max(1,R)，一格宽的逻辑束段 |
| 盾牌 | 二维圆盘x²+z²≤r²；r=2时13格 |
| 扇形 | 现有扇角、延伸倍率和高度范围内的格点 |
| 墙 | (2r+1)²×[2floor(半厚度)+1] |
| 环带 | 外圆减内圆，按现有层厚计格 |
| 柱 | 现有柱半径内圆盘×(2r+1) |
| 十字 | 现有交叉宽度与层厚内的格点 |
| 穹顶 | y≥0的球壳，按现有内外半径计格 |

计算按半径平方复杂度进行；同样参数共享派生缓存，缓存不参与存档，不影响权威结果。伤害目标数、方块扫描和派生数仍由独立性能预算限制；这些预算不降低报价的逻辑体积。

## 5. 失败返还和来源

每段当前元素e的基础返还率为r_e，全局失败损失系数为λ：

\[
r'_e=\operatorname{clamp}[1-\lambda(1-r_e),0,1],\qquad
Q_{refund,e}=\lfloor Q_e r'_e\rfloor
\]

λ初值1；设0可返还全部可追溯的存活量，设更大增加失败损失。混合魔力逐片段计算，保持元素队列和来源，不把混合来源合并为当前持有者。

| 当前元素 | 初始返还率 | 配置 |
|---|---:|---|
| 纯净 | 90% | refund.pure |
| 土 | 85% | refund.earth |
| 水 | 90% | refund.water |
| 火 | 60% | refund.fire |
| 风 | 80% | refund.wind |
| 雷 | 50% | refund.lightning |
| 光 | 90% | refund.light |
| 暗 | 70% | refund.shadow |
| 奥术 | 75% | refund.arcane |
| 寒霜（反火） | 80% | refund.frost |

其余反元素使用对应正元素比例。返还到供给源的储量，元素形态不会变成额外物品。

来源地址只由服务器运行时生成：玩家UUID、固定装置的维度与载体UUID、魔力场的维度与格点。转化、分流、合流、反相、运输和派生预付预算保留来源。蓝图不包含运行魔力，不授予返还权。

- 玩家离线、固定阵未加载、魔力场格点未加载、储量已满：保留凭据，等待原来源可接收，不强加载，也不转给附近玩家。
- 玩家和固定装置只能退回此前真实花费的净数量；返还同步抵消净消费，不虚增“收到”账本。
- 接收源在与资源相同的NBT记录中保存累计收据，重试、重新绑定和死亡克隆不会重复入账。
- 旧存档没有来源记录的量显式标记unknown；无法追溯的部分耗散，不能猜成玩家供给。
- 世界凭据初值预算65536，单步检查128，分别由`casting.refundClaimBudget`、`casting.refundWorkPerTick`设置。凭据和收据保留用于去重，达到预算时背压，不吞掉阵内待返还量。大型长期服务器需据内存和存档预算调整。

VM收支关系为：`累计注入=当前持有（含未交接凭据）+耗散+交付+已交接返还`。交接后世界返还服务拥有该数量，不能同时留在阵内。完整凭据写入世界SavedData；普通保存和加载覆盖测试已通过。Minecraft对玩家、区块、SavedData分别落盘，**本版不提供突然断电下跨文件的数据库级原子事务保证**；接收端收据可防重，但不能把此机制宣称为任意崩溃下绝不丢失的事务日志。

## 6. 自然耗散和缓存

每个世界逻辑步20Hz，分别执行：

\[
Q_{moving}(t+1)=\lfloor Q_{moving}(t)(1-\delta_m)\rfloor,\quad
Q_{cache}(t+1)=\lfloor Q_{cache}(t)(1-\delta_c)\rfloor
\]

初值δ_m=0.002、δ_c=0.05，配置`casting.movingLossPerTick`、`casting.cacheLossPerTick`。移动包括在途与待交付，缓存包括入口、本地等待、收发口和储备。零损耗可显式配置。

缓存约0.68秒衰减一半；在途约17.3秒一半。法阵内部每世界步执行8轮或64轮传输，都只自然耗散一次。停供仍衰减残留资源；已交接的返还凭据不作为阵内缓存再次衰减。断供不会自动重启。

## 7. 法强、伤害与统一效果

原生属性ID：`elementalcircuits:spell_power`，初值1，范围1–16，可经原版属性指令或其他mod属性修饰器调整：

```text
/attribute @s elementalcircuits:spell_power base set 2
/ec config set player.spellPowerCostExponent 1
```

单元素、单目标、未触上限的近似关系：`伤害=元素基础伤害×交付量E×杖端强度S×玩家法强P×反应倍率`。P只额外乘伤害，不复制资源或额外扩大状态时长。原来的128伤害上限、元素抗性、原版标签和权限继续有效。

同次命中：FIFO相克抵消→将存活量在元素/附加效果间分账→计算状态反应和伤害→一次原版hurt→仅接受后提交元素状态与灼烧/迟缓/击退。不会先单独执行“附加灼烧”再发现原版拒绝伤害。附加效果仍付出其资源份额，抵消掉的火水不能继续为附加效果付费。新版阵内汇聚不再额外套另一份相克损耗；相克在实际命中队列统一处理。

接受原版受击间隔，不清除invulnerableTime、不绕过hurt。纯治疗和无伤害支持效果保留自身语义，不伪造一次伤害。

法强在付款输出时冻结，随飞行体和派生链保存；在途换装或修改属性不改变已付法术。派生子阵继承同一份法强与魔耗倍率，不再读取命中时的玩家装备。子阵也保持用户设置的固定输入，预付不足直接失败，不自动缩小输入；未注入的可追溯预算和失败残余按相同比例返还原来源。已存在的历史冻结程序保留原策略。

## 8. 法杖耐久分段函数

0.43起，下式结果作为杖体磨损基数，再乘`board.wandWearScale`（初值0.05），累计小数。施法另独立磨损基板，固定装置也有基板耐久；此前“固定装置无物品耐久”仅指杖体。完整现行公式见[基板承载与熔断](基板承载与熔断.md)。

设单次交付量为E，杖端强度S，强度负载J=ES，实际释放间隔为Δt，频率f=20/Δt。Δt至少取当前法杖CD，第一次释放按CD估计；后续用同一物理法杖保存的上次成功释放时刻计算。

材料安全阈值J₀、f₀，超限：`x=max(0,J/J₀−1)`、`y=max(0,f/f₀−1)`。

\[
w=\begin{cases}
1,&J\le J_0\ \land\ f\le f_0\\
1+\lceil k_Jx^2+k_fy^2\rceil,&\text{其余}
\end{cases}
\]

| 杖端 | J₀ | f₀（次/秒） |
|---|---:|---:|
| 石英 | 16 | 2 |
| 紫晶 | 32 | 1.5 |
| 铜 | 12 | 3 |

`wear.<quartz/amethyst/copper>Intensity`与`Frequency`设置阈值；`wear.intensityCoefficient`、`wear.speedCoefficient`初值均1。安全区消耗1耐久；石英强度32、未超频时消耗2。计数截到剩余耐久，不让整数溢出。耐久上限仍由杖端＋杖身决定。近战维持原来单次1，杖尾决定伤害。创造施法和近战都免耐久；固定装置无物品耐久。

这里的负载是实际交付魔力量乘杖端强度；玩家法强的增幅不再额外重复乘一次物理负载。

## 9. 玩家混合回复

容量M，固定基础回复b，百分比p，药水等级L（普通1、增强2），每级额外倍率β：

\[
Regen_{sec}=b(1+\beta L)+pM
\]

无药水L=0；初值b=4、p=0.002、β=1。恢复等待仍40tick，固定步余数累计，不按渲染或离线时间补算。

容量64时，无药水约4.128/秒，普通药水约8.128，增强约12.128；容量1024时无药水约6.048。药水只放大固定项。管理员将固定回复设0并不关闭独立百分比项；两项都为0才完全关闭自动回复。

配置：`player.regeneration`、`player.percentRegeneration`、`player.recoveryDelayTicks`、`manaPotion.bonusPerLevel`。已有`/ec mana regen`覆盖玩家固定项，`/ec mana resetRecovery`恢复继承服务器固定值。魔力果实每颗＋16、成长上限1024的规则继续保留。

## 10. 天然节点与汲取

天然节点新增“累计自然恢复”和/20余数，加载不补满，人工节点仍需要水晶。

- 只在已加载且进入本步活动预算的场格点推进恢复和补能；停用场、卸载和超出当步预算时冻结，不计算离线收益。
- 恢复初值g=1魔力/秒，配置`field.naturalRegeneration`。
- 节点更新：`N'=min(容量,N+gΔt)`；向场注入`min(剩余量,本步输出上限,场空位)`，只扣实际接受量。
- 默认天然节点容量4096，每5tick输出至多0.5，相当于上限2/秒；满速抽取时净消耗约1/秒，最终长期输出受自然恢复约1/秒限制。
- 节点守恒：`初始＋水晶补入＋自然恢复=当前剩余＋累计释放`。

同一载体上运行中的汲取口总数n，单口速率a，当地场量q，满速参考场量q₀：

\[
A_{tick}=\min\{q,\ n a\min(1,q/q_0)\}
\]

初值a≈0.2/世界步，q₀=8，配置`field.intakePerTick`、`field.intakeReference`。多口增加吞吐额度，所有槽位仍竞争同一份有限格点资源；不会每口复制一份场。节点释放提高当地浓度，汲取降低浓度，低浓度又降低汲取率，形成自然反馈。单个口还受其符文设定、输入节拍与缓存空位限制。

汲取光束示例现在明确配置作用量1/16，能够由单口供给支付；大型法术应增加汲取口或降低作用量。

## 0.36 装备属性扩展

有效容量改为永久容量加装备容量；魔力果实只检查永久容量，穿齐法袍额外增加88。固定恢复分支加入装备恢复：`(玩家固定值＋装备固定值)×药水倍率＋有效容量×百分比`，整套额外固定恢复2.75/秒。穿戴只扩大容量、不补能；卸下截断超额魔力。玩家槽现场v2分别保存永久容量和装备额外值，旧v1的装备额外值显式为0。

法强使用既有原生属性叠加，整套增加0.55；伤害与成本指数关系保持。装备施法使用相同资源账本、来源退款、自然损耗和玩家池，独立装备冷却。网络升级为`1.21.1-18`；法术包和递归链附带可持久化反击来源，不改变既有元素伤害类型。完整规则见[法袍戒指与装备施法](法袍戒指与装备施法.md)。
