# 物料与红石自动化

版本：0.50.0，Minecraft 1.21.1 / NeoForge。实现日期：2026-11-05。

## 组合规则

- 拆解：输入 → 土转化 → 反相 → 施法方式/形状 → 输出。仅反相土的剩余作用量支付拆解；其他元素不能为它垫付成本。按既有队列先反应，再分配到目标。
- 构筑：输入 → 土转化 → 容器读取 → 施法方式/形状 → 输出。也可交换土转化与容器读取顺序。读取符文只添加物料来源修饰，接触方块时才提取真实库存。普通地元素不凭空创造方块。
- 回收：在拆解通路中加入容器输出。正常战利品进入指定容器，剩余物品在被拆解处掉落。该符文只处理这次拆解的产物，不吸走附近无关掉落物。
- 红石：红石感应 → 信号线 → 通路开关（改为信号模式）。魔力通路穿过该开关。可在信号通路中插入反相、计数、节拍或翻转锁存，不增加模式管理页面。

容器与红石端口属于固定法阵。先用调律杖启动；持续法阵按步读取红石。红石低电平是有效信号，不等于断供；暂停、失效及手动停阵仍遵循既有生命周期。红石不会绕过基板熔断、供魔成本和输出预算，也不自动启动已停阵的载体。

## 容器与参数

容器必须紧邻固定法阵。方向采用世界坐标，通过现有符文参数栏编辑：0下、1上、2北、3南、4西、5东。读取和输出可分别选择不同面，也可连接同一容器。容器通过 NeoForge 的有侧 ItemHandler 访问，尊重该侧允许的提取/插入；不额外加载区块。

沿用当前世界修改权限契约：所有者须在线且处于同一维度，具有建造和目标位置交互权限；离线时不进行拆解、构筑或容器存取。首期没有为离线玩家引入新的假玩家权限代理。

同一路法术可以分别指定一个读取面和一个输出面。合流时同类方向冲突会拒绝组合，保留原有输入，不随机选择。槽位按容器原顺序选择第一个符合筛选条件、可提取或可放置的物品；物品不足时停止对应放置，已经完成的目标不撤销。

红石感应的参数为1–15强度阈值，默认1。读取法阵六面中最高的真实邻居信号，达到阈值输出高电平。输入按世界tick采样，沿用现有信号线路的下一步生效规则；持续高电平交给计数/锁存时不会凭空重复上升沿。

## 成本与物料守恒

默认拆解成本：`1 + max(0, 硬度) × 1` 点有效土魔力/方块；默认放置成本：1点有效土魔力/方块。法强/效率先由既有接触流程折算，不能重复计入。范围和形状沿用统一有限分配及可见性规则，不穿墙采矿。实际耗用还包括输入、形状、连线和符文等既有成本。

拆解使用普通无附魔钻石镐的战利品上下文，不附赠时运或精准采集，尊重 `doTileDrops`。使用原生破坏、掉落与放置兼容事件；事件取消不进行对应写入。创造模式的所有者也须支付容器实物，不能用自动化复制库存。

先模拟读取、检查放置状态与空间、通过事件、再复核并提取。提取后写入失败则优先退回容器；无法退回时在原地生成返还物，不受关闭普通掉落规则影响。容器满时回收剩余产物在原地生成。法阵移除、容器更换或权限变化时再次校验，失效的发射物绑定不获得匿名物料权限。已有在途法术保存UUID绑定，历史包缺少物料修饰时迁移为空。

## 配置与首期范围

服务器配置 `automation.enabled`、`breakBase`、`hardnessCost`、`placeCost`、`maxHardness`、`maxContainerSlots`。初值分别为1、1、1、1、50、128。其余法术目标、形状扫描及派生预算照常生效。

首期放置限于普通BlockItem对应的单格实心方块；不放置容器、机器、门、床或有独立状态的物品。拆解跳过不可破坏、流体与带BlockEntity的方块，避免损失容器内容或法阵设计。物品不会预先从容器进入魔力缓存。手持法杖仍可用反相土拆解，但容器符文的物料访问只授予固定宿主；首期不把玩家背包当作隐式仓库。

递归子法阵暂无独立外部物料端口绑定；应在固定主阵的输出通路安排读取/回收。输出、派生与法强修饰保留已经绑定的主阵物料信息，投射物不会凭命中位置访问陌生容器。物料筛选符文使用物品注册ID（如 `minecraft:oak_log`）或标签（如 `#minecraft:logs`）；条件同时约束容器取料与拆解产物入箱，不匹配的掉落留在世界中。该符文只修饰物料通路，不创建库存操作，也不改变权限检查。

## 验证

核心契约162,647项断言通过，覆盖物料修饰组合、冲突、成本默认值补齐、在途包往返与旧包兼容、符形资源、红石高低电平和现场恢复。原生266个GameTest全部通过，覆盖实物消费、硬度预算、拆解掉落、空/满容器、事件取消、锚点移除、基岩、带状态方块、权限，以及宿主采样真实红石。额外检查高成本配置配合低强度法杖时，无法支付的目标不会使法阵进入故障状态。尚未进行本次界面的人工游戏试玩。
