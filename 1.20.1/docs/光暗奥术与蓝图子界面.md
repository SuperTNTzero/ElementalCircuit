# 光、暗、奥术与蓝图子界面 · v0.5.0

日期：2026-10-29。分支：`codex/minecraft-light-arcane-blueprints`。平台仍为Minecraft 1.20.1 / NeoForge 47.1.106 / Java 17。原Godot玩法代码未在本轮修改。

## 玩法与试用

1. 法杖编辑器载入光束示例，将元素转化改为“光”，保存后对墙或地面施法。命中处的合法空格会产生15级、持续200个服务器步（正常20 TPS下10秒）的临时光源；射线沿途也有短时真实照明。光球飞行时逐格照亮环境，命中处的光仍按有限预算分配。
2. 将元素改为“暗”，瞄准火把、营火、蜡烛或常见灯块。火焰、营火和蜡烛真正熄灭，不会到期自行重新点燃；法术光被移除；火把和常亮灯块暂时压暗200步，再恢复原方块及朝向。
3. 将元素改为“奥术”，在僵尸前放石墙，再施放光束或球状弹道。正相奥术穿过方块和流体命中墙后的生物，墙体保持原状。正相奥术范围作用也可穿过范围内的方块遮挡。反相奥术保留原碰撞行为。
4. 编辑器底部“法阵蓝图”进入独立子界面。导入页提供多行文本框、粘贴按钮与导入草稿按钮；导出页点击“生成并复制”，生成当前草稿文本码并写入剪贴板。返回后点击“保存图纸”才请求服务器应用。

压暗支持普通/灵魂/红石火把及壁挂版本、萤石、海晶灯、菌光体、三种蛙明灯、南瓜灯、点亮的红石灯。暗不修改天空光、不全面接管其他模组的发光方块，也不替换容器或带方块实体的光源。红石火把在压暗期间也失去其信号输出，恢复后重新参与原版更新；点亮的红石灯恢复时依据当前红石输入决定是否发亮。

临时光没有物品形式和掉落物，不可作为可带走的免费材料。压暗源保留原始来源和属性，破坏时按原方块掉落；支撑消失时遵循原火把生存条件。当前压暗外观使用熄灭红石火把/深色灯纹理，占位外观不改变服务器光照结果。

## 有限作用量与生命周期

新规则位于`data/elementalcircuits/rules/radiance_v1.json`，由独立严格加载器注入。临时光每个接收格最低1点作用量；压暗和熄灭沿用世界交互规则的0.25点最低成本，并按杖端强度换算。光的治疗与方块照明仍共享同一份按成分分配的预算。

弹道照明在发射时从正相光成分中最多预留四分之一，每个照明步支付1/64点作用量，向上取整扣费，最多128步。扣除后的包用于最终命中；光束每个经过的不同格消耗一个预付步，球状弹道每个服务器推进步消耗一个。实际照明格保留3个服务器步并可续期；无效/被取消的放置和飞行提前结束时，未交付预算耗散，不退款或再次复制到命中效果。其他元素成分不为光照扣费。光束为瞬时效果，其路径短光也只保留3步。

每个维度最多记录1024个临时光/压暗位置。相同格子续期取较长剩余时间；短光不会提前删除已有长光。`WorldIllumination`负责服务器固定步寿命，完整保存期望方块状态和剩余步数，不按渲染或离线时间恢复/倒计时。卸载格冻结；清理所需相邻区块未加载时暂缓恢复，不为照明加载区块。

到期只修改仍与记录匹配的方块，玩家后来替换成其他方块时仅清除记录。压暗源的原状态同时编码在区块方块状态中，避免光照SavedData丢失时永久吞掉原灯；原生计划刻检查孤立标记，恢复原灯或移除孤立法术光。损坏的光照数据保留原文并停用，不以空数据覆盖。

所有新增照明、压暗和熄灭先检查维度高度、边界、已加载区块、玩家建造权限与`mayInteract`，发布同一可取消的`ElementBlockChangeEvent`预检，并在提交前重新校验。自动到期恢复处理已拥有的临时状态，不再次消耗玩家资源。领地插件及其他动态光模组的兼容矩阵尚未验收。

## 奥术投送与历史语义

`SpellPayloads`将含正相奥术的混合包拆为普通支路与纯正奥术支路，逐成分精确保留支付量和形式。只有奥术支路跳过方块/流体碰撞与范围地形遮挡；一小份奥术不会让其余火、水、光等成分免费穿墙。实体首次接触和玩家伤害约束继续生效；奥术弹道仍由有容量的法术盾拦截，不强制加载射程内区块。

世界法术SavedData升至v4，新增`Trail`预付照明剩余步数；新弹道`Effects=3`。v1/v2继续迁移到历史`Effects=1`；v3按原`Effects=1/2`保留行为，照明预算为0。旧在途奥术不会升级后突然穿墙，旧光球不会突然新增方块光。新弹道的强度、拆包结果、扣费后的命中包、剩余照明、位置、方向和射程一起保存。临时光照独立SavedData为v1。

## 蓝图数据与界面边界

文本码格式为`EC1.<Base64URL压缩JSON>.<CRC32>`，编码稳定，解码限制输入字符数、解压字节数、UTF-8格式、版本及校验值，拒绝尾随压缩数据和不完整内容。CRC用于发现复制损坏，不是来源认证。仍兼容此前直接导出的JSON；不兼容Godot历史蓝图码。蓝图只保存配置，不含装备部件、身份、资源库存、运行信号或临时光源。

导入先解码并用当前载体的冻结规则重新构造完整蓝图，格盘放不下整次拒绝，不扩大基板、不补魔力。成功后作为一次草稿变更，可由原编辑器撤销。失败留在子页，保留文本和旧草稿；取消返回也不写入草稿。服务器应用仍走既有停阵、完整校验与资源回收流程。

`BlueprintTransferModel`只持有子页状态和纯编解码/导入校验，`BlueprintTransferLayout`计算布局，`BlueprintRenderer`只读绘制，`BlueprintScreen`装配输入、剪贴板及页面跳转。后台编辑器刷新包仍转交原父页，不关闭子页、不自行推进VM。导入与导出输入分别保留，窗口缩放不会清空文本；导出以点击时的当前草稿重新生成。

本轮验证结果、产物与截图见 [验证记录](验证记录.md)。尚未完成真人生存平衡、多人压力测试、长时区块卸载/服务器崩溃矩阵与GPU性能验收；自动客户端验收是无世界的编辑器流程，世界光照由真实服务器光照引擎GameTest验证。
