# 底层抽象与运行边界重构

日期：2026-10-29。目标版本：v0.11.0 / Minecraft 1.20.1 / NeoForge 47.1.106 / JDK17。根工作区与独立模组仓库任务分支均为 `codex/minecraft-runtime-boundaries`；未暂存、提交、合并、tag 或推送。

## 审查结论

此前 `domain` 的定点 VM 已与 Minecraft 隔离，但外围的状态所有权和阶段职责没有贯彻同一边界。问题有实质后果：

| 原问题 | 已实施修改 | 验证方式 |
|---|---|---|
| `WorldCircuits` 同时解析装备、推进 VM、执行效果并序列化 | 纯应用调度器、宿主能力和网络交换接口；Minecraft 层只装配适配器 | 无引擎宿主执行相同阶段；稳定顺序、跨阵因果、故障隔离、重复身份拒绝 |
| `CarrierService` 混合缓存、NBT、编辑命令、观察与调度 | 仓储、命令、观察、装备、材料、故障模块独立；原入口保留薄兼容委托 | 正常刻印、材料/工作台、书籍切换及真实施法回归 |
| 服务器/编解码导入客户端 `AssemblyInspection` | 观察类型移入独立应用包；抽象快照成为独立 `CircuitSnapshot` | 自动依赖规则拒绝核心层引用引擎/适配器/客户端；契约不引用具体 VM |
| 每步完整序列化，SavedData 每步标脏 | 聚合变更标记、仓储按变更提交、玩家池按状态值提交、网络独立标脏 | 待机连续运行不替换原 NBT 标签；嵌套状态变更与运输全损耗正确标记 |
| 合法大法阵/蓝图簿真实 NBT 编码丢失 | 有版本、有字节限额的 UTF-8 ByteArray，严格读取与旧格式迁移 | 16页卷册、四槽64符文/64线路法术书同时通过压缩NBT和实际物品网络字节往返 |
| 固定设备依赖在线实体 | 独立宿主使用本地储量、位置、方向和所有者UUID | 在线解析返回null仍推进并扣真实本地储量，保存后完整恢复 |
| 销毁端点和卸载端点无法区分 | 锚点v2持久所有者/销毁状态；受权清理、在途入损耗 | 卸载拒绝吞包，销毁后所有者可回收，其他玩家拒绝，迁址不冒充原端点 |
| 缺失所有者可绕过玩家权限 | 权限模块保留身份，缺失所有者不获得匿名编辑/PvP授权 | 对生物、玩家、自身及方块的权限回归 |

详细职责、所有权和调用规则见 [架构说明](../ARCHITECTURE.md)。本次没有改变元素、符文目录、资源损耗公式、逻辑初态协议或既有手动起阵规则。

## 保存与迁移

存储外层格式为 `{Format:1, Utf8:byte[]}`，内层程序集v1、VMv3、蓝图簿v1保持原语义。限制仍为程序集1MiB、卷册512KiB；旧字符串只有完整解码及校验成功才替换。拒绝未知格式、非法UTF-8、超限、缺身份和错误根类型，不以空阵或新身份替代损坏现场。缓存遇到整条 NBT 替换会失效；其活动编码由仓储独占写入。

世界互联保存升级v2，保留运输和守恒账本，增加锚点所有者与销毁状态。v1可以读取；缺失的所有权不凭空猜测。升级前已经丢失且无所有权证据的旧端点仍拒绝自动恢复。已经被旧版写空的数据需从旧备份恢复。

网络协议升为8，客户端和服务器一起更新。领域快照 Java 类型拆出属于内部API调整，不改变保存JSON字段。

## 验证

最终执行：`build runGameTestServer runClient -PeditorSmoke=true`，使用本地JDK17、离线Gradle缓存；日志 `build/refactor-final.log`，退出码0。**74,252项核心断言、67项GameTest、61张真实客户端截图与对应交互检查全部通过**。独立核心脚本同样通过；原Godot统一隔离回归23套通过、失败0，日志 `build/refactor-godot.log`。

新增服务器测试覆盖真实磁盘编码字节与物品网络字节，不以 `ItemStack.save/of` 的内存树往返替代。依赖检查与纯调度测试纳入常规 `CoreContracts`。客户端完成61阶段标记，检查旧刻印、基板/互联、蓝图文本子页、工作台、16页实体簿和四槽法术书；目视检查管理页与紧凑蓝图簿，未见控件覆盖/越界。没有进入正式玩家世界。

初次最终构建停在ForgeGradle启动环境的HTTPS探测，线程栈明确落在 `EnvironmentChecks.testServerConnection`；停止仅本次构建进程后，用 `-Dnet.minecraftforge.gradle.check.certs=false --offline` 跳过这一启动探测。未持久修改Gradle/TLS设置，依赖全部来自本地缓存。最终组合日志无ERROR，保留平台/音频/弃用WARN。Godot既有根证书日志按统一入口规则单独识别。

## 性能解释和剩余工作

沿用审查场景：每载体四槽、每槽64个无线路信号符文，全部停供；每档预热10次、测40次，只计 `WorldCircuits` 入口。新增回归检查待机过程中 NBT 编码对象保持原引用，因此提速与跳过完整序列化有直接行为证据。

这不是整个 Minecraft tick、JMH、GPU、真实联机带宽或长时GC验收。统一 GameTest 中大量同步构建/测量仍可能输出“Can't keep up”，不能据此宣称整服达到某TPS。粒子仍按原版逐点广播；客户端形状事件/预算渲染仍待处理。`JsonCodecs`、`WorldSpells` 还有可进一步按子域整理的职责；保留明确边界，不宣称所有工程目标已经全量达标。

副手法术书的旧测试使用随机载体UUID和默认散布，偶发把合法偏移判为施法故障。本次拆开磨损/命中断言，并在该命中用例中显式配置零散布精度符文，使其稳定验证书杖绑定与实际命中；保留原运行默认散布。
