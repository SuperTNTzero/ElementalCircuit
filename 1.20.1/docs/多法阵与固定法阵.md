# 多法阵、基板安装与固定法阵

版本：0.6.0；Minecraft 1.20.1 / NeoForge 47.1.106。

## 操作

刻印界面底部新增“法阵管理”，分为“法阵、互联、基板”三个子页。右侧“基板”按钮也直接进入安装页。

- **基板**：直接点击木头、黄铜或水晶安装，不必逐档经过。消费背包中一张目标基板，回收旧板，并同时保存当前草稿。运行中、布局放不下、缺板或仍连接其他法阵时整次拒绝。木头/黄铜/水晶仍分别为61/127/217格。
- **法阵**：每个法杖或固定方块最多四个稳定槽位。新增槽位消费一张所选基板；新阵为空白、无额外魔力。各槽独立基板、草稿、缓存、控制态和起停。选择槽位后返回刻印；法杖普通右键起停选中槽位，其他已启动槽位继续运行。切换页面或刷新不会清掉其他槽位的未保存草稿。
- **互联**：先在两端放置并保存发送、接收符文，再停止两端，在子页选择载荷、发送口和接收口，点击“建立连接”。内部连接支持同载体的不同槽位；固定方块还会列出16格内、同维度、属于自己的已加载固定法阵。列表可滚动，长文字有悬停提示。

| 符文 | 所在目录 | 接线 |
|---|---|---|
| 魔力发送 | 魔力流转 | 阵内魔力线接入；由互联页选择目标 |
| 魔力接收 | 魔力流转 | 接到后续转化、塑形或输出符文；不自动从玩家槽取魔力 |
| 信号发送 | 逻辑与控制 | 阵内信号线接入；仍支付控制成本 |
| 信号接收 | 逻辑与控制 | 输出信号，可连接门、开关或其他控制逻辑 |

发送口保留魔力组成与已有法术修饰，不直接在世界施法；只有输出符文交付法术。纯信号阵也可独立手动起阵。

## 一个法杖上的两阵实验

1. 阵1刻印并保存：`魔力输入 → 火元素转化 → 魔力发送`。
2. 在法阵管理中消费一张基板新增阵2，刻印：`魔力接收 → 指向施法 → 光束 → 法术输出`，选择持续模式并保存。
3. 两阵均停止时，进入互联页，选择阵1发送口、阵2接收口，建立魔力连接。
4. 分别手动启动阵2、阵1。阵1从玩家槽取魔力并元素化，阵2接收后发射真实火光束。两阵共同使用玩家有限槽，不能通过新增法阵补魔力。
5. 可将信号控制逻辑独立放在阵3：`常量信号/门电路 → 信号发送`；接收阵通过`信号接收 → 信号控制开关`决定魔力能否进入元素转换或输出支路。

槽位1先于2、3、4支取同一供给；没有公平调度或额外并行供能。

## 固定法阵方块

生存配方：`空 木质基板 空 / 石头 铜锭 石头 / 石头 石头 石头`。创造物品栏名称“固定法阵”。每件不可堆叠。

- 放置后正面为箭头方向，决定指向施法方向；范围施法以方块为中心。右键打开该方块的刻印界面。
- 新方块本地储量为0、容量128。蹲下右键或管理页“充能”从玩家槽转入16点；剩余空间不足时只转入实际空余量。不使用离线恢复，不自动从玩家远程抽魔力。充值不足整次拒绝。
- 方块所有者可在8格内编辑、起停、充能或回收；其他玩家不能操作。两个固定法阵距离不超过16格可互联。内部连接不占对外输出额度；每载体只允许一个槽位向外输出。
- 方块按20Hz世界步推进，强度1×；没有法杖部件或耐久。法杖保留杖端速度与强度，多阵共享该法杖部件和磨损。
- **v0.11运行条件：区块已加载，设备具备有限本地供给和有效原锚点。** 不依赖所有者在线或同维度，不强加载区块、不补算现实离线时间。所有者身份仍用于效果权限；离线玩家的方块修改不会降级为匿名授权。因魔力耗尽停阵的仍须手动重启。详见 [架构说明](../ARCHITECTURE.md)。
- 活塞无法移动，具有高爆炸抗性。尚有外部线路时正常挖掘被拒绝。先让待发与在途魔力排空、停止两端，再逐条断开线路，之后才能回收。回收的一件物品完整保留身份、槽位、内部连线、运行现场和本地储量；重放后保留现场。创造模式中键只复制空白方块，避免复制运行身份。

跨载体连接首期只支持固定方块；法杖随身移动只保留自身槽位间的内部连接。没有跨维度、移动无线网络、物流导管或区块加载器。外部锚点不匹配时冻结连接。

## 因果、守恒与保存

每个世界步严格按“交付上步运输 → 推进所有法阵 → 发布新运输”执行。铜杖端即使在一世界步推进两次法阵，也不能跨过此互联边界，反馈不会在同一步无限运行。

魔力接口单次运输保留率约99%，逐成分均分、余数按保存的连接顺序处理。一对多不是复制。每条线有独立有界运输缓存；满载、接收阵未启动或接收口不兼容时保留包并产生背压。同一发送口的新包要等所有分支有空位，已发布分支可分别交付。线路和发送口仍有魔力时拒绝断线，不截断或凭空回收。一个发送口不能同时用于内部、外部两种网络，需放置独立发送符文。

信号可广播；有效性与真假分开保存。源阵停供后对外无效，接收阵不会把失效当作有效假经过非门生成伪真。内部传播仍遵循逐线固定步延迟；断供保持内部控制现场，补能不自动起阵。

配置冻结在载体/法阵/网络内：最多4槽位，每组内部最多32线，每维度固定法阵网络首期最多32线。端点使用载体UUID、稳定槽位号和符文ID。世界外部连接、锚点、控制有效性、在途包和收支由维度SavedData保存；本地法阵组由物品/方块NBT保存。重复的运行身份在同一调度边界停用，避免创造复制品同时参与资源转移。

旧单法阵`Runtime`显式迁移成槽位1和空互联网络，保留基板、缓存、时钟、控制和收支，不赠送新板、不重置魔力。VM现场v1读取为无接口状态，保存升级为v2；法阵组/互联现场v1，网络握手v3。蓝图仍只含单阵创建配置及收发符文，不含槽位组、运行魔力、外部对象身份或世界线路。不能靠导入复制资源。

暂未覆盖跨区块文件崩溃时的原子保存、恶意管理员指令强删方块或伪造NBT恢复策略；正常保存/重载和暂时卸载有测试。未将短时测试称作大型网络或长期性能验收。

## 实现入口

- `domain/CircuitAssembly`：稳定槽位与独立运行现场；`CircuitLinks`：延迟运输、分流、背压和账本。
- `domain/TickCircuit`：收发符文、信号有效性和VM现场。
- `server/WorldCircuits`：世界阶段调度；`WorldCircuitLinks`：固定锚点与维度保存。
- `block/CircuitBlockEntity`：有限储量与完整载体；`CarrierService`：权限、安装和迁移。
- `client/AssemblyScreen`仅装配输入/网络/控件；`editor/AssemblyPageModel`管理选项，`render/AssemblyRenderer`只画页面。
