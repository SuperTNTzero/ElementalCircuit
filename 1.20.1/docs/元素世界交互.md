# 元素世界交互 · v0.4.0

此页保留v0.4规则与验证范围。v0.5新增光、暗、奥术环境效果、弹道协议和蓝图子界面，见 [光暗奥术与蓝图子界面](光暗奥术与蓝图子界面.md)。

日期：2026-10-29。分支：`codex/minecraft-element-world`。本轮优先把元素接入Minecraft环境，首批实现火、水、风、雷。用户明确要求火与水可以创造火焰、水源，已作为正式行为接入。

## 已实现的效果

| 元素 | 正相世界作用 | 反相世界作用 |
|---|---|---|
| 火 | 在合法空位创造原版火焰；点燃营火/蜡烛；将冰和霜冰融成水 | 熄灭火焰/营火/蜡烛；将已有水源冻为会融化的原版霜冰 |
| 水 | 在空位创造原版水源；熄灭火焰/营火/蜡烛；湿润耕地 | 干燥耕地 |
| 风 | 推动真实掉落物，可用于输送/聚散物资 | 将掉落物吸向作用中心/施法者方向 |
| 雷 | 激活避雷针的原版红石脉冲；去除一层未涂蜡铜锈 | 提前泄放避雷针脉冲 |

生物伤害、治疗、状态与击退入口仍存在。表中的世界响应由服务器实际改动方块状态或实体速度，与粒子开关无关。土、光、暗、奥术本轮沿用原有生物/屏障效果，尚未新增环境响应。

水源是普通Minecraft水源，生成后可流动、取水、参与水/岩浆反应，按原版规则保存到区块。火焰是普通火焰，受支撑、雨水、燃烧蔓延与`doFireTick`规则影响；不会因为一轮粒子结束就删除。原版后续水源再生与燃烧扩散遵循Minecraft规则，不按初始放置数量限制自然演化。下界生成水会消耗本次作用并蒸发，不会留下水源。

本轮没有把水定义为土系临时物质，也没有开放永久土料。反火冻结现有水使用原版霜冰，到期由原版机制重新融水，不能采集成免费的永久冰资源。

## 怎么试

1. 创造模式取法杖，打开编辑器，载入“示例 / 光束”，保存。
2. 在石质地面前放一面小墙，对准墙面施放火元素；命中面外侧合法空位出现真实火焰。空位不合法或交付量不足时没有方块生成。
3. 停供，将转化符文改成水，保存后对准同一位置施放：先灭火，再施放可在空位生成水源。水会自行流动。
4. 分别测试未点燃营火、干耕地、避雷针及氧化铜。风/反风对准掉落物，可看到物品被推开/吸回。
5. “范围施法＋球状”在中心附近可见表面分配预算。扩大半径会按既有参数规则降低交付强度，预算太小可能只能影响少量位置。

指向光束在首次生物、可命中的掉落物或地形/流体接触处结算；生成位置为命中面外侧的空格。风可直接命中掉落物，其余元素的光束不会被掉落物截走。球状弹道在接触或射程耗尽处做范围结算。范围创建选取有坚固上表面支撑的空位，避免凭空填满整个空气球体。纯净不产生世界效果；盾牌的拦截职责不变。

## 同一份作用量

显化先确定可响应的生物、物品、方块快照，再将每个元素正/反相的份额统一分配。不会在伤害完生物后再把完整魔力复制给每个方块。

默认规则位于`data/elementalcircuits/rules/world_interactions_v1.json`：

- 每个原始火焰或水源至少需要1点作用量；点燃、熄灭、冷热转换、耕地与铜/避雷针状态响应至少0.25点。
- 预算按元素成分单独分配，只发给能响应该成分的目标；不能支付动作阈值的接收者按稳定顺序裁减，剩余接收者均分，固定顺序分配余数。2点水作用最多初始放置2个源，不会因为覆盖20格就复制为20份。
- 每次最多128个接收者，优先距离最近，其次稳定键；固定16.16分配不依赖查询返回顺序。杖端强度只换算该份额的世界作用，不改变VM资源账本。
- 没有接收者、低于最低成本、被遮挡、权限不允许、提交时状态已变或事件取消的份额耗散；不会返还成免费魔力。
- 一个方块在同一次接触快照中至多提交一次状态变化。火水同时作用不能在同一步反复生成/消除同一格并重复领取效果。

这些数值是Minecraft游戏动作预算，不是焦耳、质量或完整物质守恒模拟。真实热传导、热容量和质量/做功仍遵循原方案的后续目标，本轮没有将简单方块转换重命名为完整物理。

## 实现边界

`EffectDistribution`为不依赖Minecraft的纯分配器；`WorldInteractionRules`是专用版本化数值。`ElementInteractions`负责接触快照、响应能力、分配和有序提交；原`SpellEffects`负责投送及生物适配，`WorldSpells`仍拥有弹道/屏障。没有建立第二套运行时VM。

范围方块和掉落物检查遮挡，墙后目标不因为进入半径就生效。不强制加载区块，位置必须在世界高度与边界内。玩家还需具备建造权限并通过`ServerLevel.mayInteract`；来源玩家不在该维度时，尚未交付的方块修改不执行。

方块修改发布可取消的`ElementBlockChangeEvent`，继承原版平台的`BlockEvent.EntityPlaceEvent`，已有放置监听器可接收。该事件是提交前预检：`getState/getPlacedBlock`给出拟放状态，快照和世界仍是旧态。取消时不会先放水再撤回，避免提前触发水/岩浆反应。事件允许后再验证目标并提交。没有覆盖容器或其他非空方块来生成火/水；已生成流体的后续自然影响由原版规则接管。

世界法术现场升至v3，每个在途弹道保存`Effects`：1为历史实体响应，2为本轮环境响应。旧v1/v2存档显式迁移为Effects=1，保留旧强度、位置、资源、方向和剩余射程；新发射弹道使用Effects=2。恢复旧在途火球不会突然新增地形点火。生成的原版水/火、霜冰、红石计划刻由Minecraft区块/计划刻保存，不另存一套方块镜像。

## 元素后续方向

| 元素 | 下一阶段方向 | 必须保留的条件 |
|---|---|---|
| 土 | 临时土墙、桥和修补 | 身份/来源、真实维持支付、断供倒计时；采集加工不能永久化 |
| 光 | 可维护的照明与显形 | 光源所有权、供能/结束和加载恢复；不能覆盖玩家灯具 |
| 暗 | 遮光、遮蔽与感知干扰 | 明确影响哪些光源和目标，不永久删除外部方块 |
| 奥术 | 法阵/屏障的资源与结构交互 | 显式目标、能力与支付，不成为万能破坏/免费供能 |
| 火/水 | 连续冷热、含湿及相变 | 热容量、传热、材料状态与预算，不只用阈值换方块 |
| 风/雷 | 运输、机械与导电网络 | 质量/做功、导电路径、承载能力及耗散账本 |

当前新增范围是首批四元素交互，其余表项没有视为完成。真人生存平衡、联机领地插件兼容和长期性能需独立验收。
